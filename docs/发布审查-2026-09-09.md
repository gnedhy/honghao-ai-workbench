基准：origin/main 017fa7a → ce663d3，包含 86b3f02、23a2976、ce663d3。规格：Issue #23、ADR-0006 至 0008 及后续用户验收要求。草稿 PR：[#57](https://github.com/gnedhy/honghao-ai-workbench/pull/57)。

用户在完成单版本保留清单核对后，授权按审查、PR、合并、正式启动、验证的顺序推进；清场仍须最终结果汇报后另行确认。本记录更新早先仅授权提交推送的阶段性边界。

## Standards

两项审查发现，未提出冻结版本风格重构：

1. 清场前置问题：标准快照遗漏采购来源 Excel。`api/operations.py` 的快照枚举与允许路径仅覆盖原有知识文件；`api/procurement_excel.py` 新增采购原件。已有独立原件备份与恢复路径、哈希验证作为本次补偿；最终唯一归档必须包含它，不能只凭标准快照成功而删除原现场。
2. 数据安全问题：`api/procurement_excel.py` 将包含 `anomalies[*].value` 的完整首次导入预检结果交给 `admin_event`，原样进入管理审计表；与模块启用清单“不记录敏感字段值”冲突。建议新导入审计仅保留来源哈希及计数，价格原文继续在受控原件和业务来源表追溯。既有历史审计暂不修改，待确认处置口径。

## Spec

一项回退完整性缺口：标准快照遗漏采购原件，与 ADR-0007 来源保留及 Issue #23 回退要求不完全相符。已有补充恢复验证可覆盖本次发布归档，但唯一归档尚未最终形成，不能清场。

核对共同录价与启用分离、转授权限制、即时基线不混入取消或其他排期、历史比较前一版本、待发布排序及比较逻辑，未发现新的核心价格或授权阻断。已知单笔高波动二次提示按用户冻结决定保留。

- OSV querybatch 对 31 个已安装 Python 依赖查询，未返回已知漏洞匹配；请求仅包含公开包名和版本。原 pip-audit 的系统策略错误保留，不冒充该工具已成功。
- 采用仓库合成工作簿 fixture，在独立临时数据目录完成 active → off → prototype → active 启停演练；采购接口分别返回 200、404、404、200，账号与模块注册接口始终正常。
- 每阶段所有采购表逐表指纹相同，重新启用仍读取 20 版价格。本演练没有触及候选库或用户验收数据，也没有为了测试而启用其他业务模块。
- 前序完整门禁 226 项后端、25 项前端、构建及自动安全检查通过。当前应用代码未变；未将这些结果替代本次独立审查。

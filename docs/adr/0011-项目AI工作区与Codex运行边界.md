# 项目 AI 工作区采用 Codex，保留产品与权限边界

状态：已接受产品方向，实施与启用分阶段验收。依据为用户确认的 H00—H13 计划、[H01 技术交接](https://github.com/gnedhy/honghao-ai-workbench/issues/73#issuecomment-5992135820)，以及 2026-10-05 确认先上传下载、后评估目录关联的决定。

项目 AI 增强现有聊天与任务，以个人项目组织资料、连续任务、项目规则和技能；保留采购、研发、销售工作台，不新增职能工作台或运行时注册框架。固定 Codex 内核连接 DeepSeek，产品层维护身份、任务、文件版本、权限与执行事实；通信集中在受控接入处，不把员工个人配置或内核持久化结构当作产品数据库。H01 的固定基线为 Codex 0.160.0，升级与回退在 H11 验证，实验性能力的适用性继续作为 H13 上线判断事项。

## 替代的旧约定

| 原约定 | 新约定与保留边界 |
| --- | --- |
| ADR-0004：DeepSeek Harness 首选 | 首期基座改为固定 Codex；版本锁定、事件标准化、受控目录、预算和故障时保留业务记录继续有效 |
| 原领域定义：每次工作提交新建任务 | 首次工作提交创建任务；继续、补充和修改保持任务 ID，新的独立目标从“新聊天”建立；旧任务不自动合并 |
| 原领域定义：技能不归属项目 | 同时支持通用技能与项目技能；版本和实际调用须留证，技能不授予额外权限 |
| ADR-0003：必须由固定工作流包裹执行 | 首期直接以受控任务运行承载执行，有界循环和人工写入边界保留；工作流页面及入口撤下，历史记录不删除 |
| ADR-0001：轻项目只聚合可选上下文 | 明确个人所有权、规则和项目技能；创建时的任务项目关联继续冻结，不增加成员、排期或里程碑 |

文件能力先实现选取文件／文件夹上传、服务器原件快照与工作副本、成果版本下载；H09 目录授权暂缓且不阻塞本轮验收。知识库保持关闭，技能接口改归聊天／项目能力，不为旧 `/api/skills` 路由归属启用整个自动化模块。多 Agent、自动调度和插件目录仅保留后续评估 Issue。

正式业务写入仍走现有业务模块及其确认与权限流程，首期 AI 仅接入获授权的只读查询。项目规则、技能和导入文档均不能绕过这些边界。内核不可用时阻断 AI 执行，项目记录与成果保留；合并、部署、模块启用分别留证，四项启用确认及实际重启核验不由本 ADR 代替。

领域术语见 [CONTEXT](../../CONTEXT.md)，页面、状态与逐阶段验收见[领域与交互设计](../business/项目AI工作区-领域与交互.md)。

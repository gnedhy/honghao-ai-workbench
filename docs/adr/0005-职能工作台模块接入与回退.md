# 职能工作台采用静态注册、独立开关与向前兼容迁移

职能工作台保留中台统一外壳，采购、研发、销售和总经办模块通过固定 `WorkbenchId` 接入，不建设动态插件、微前端或独立 UI 外壳。模块状态由服务端分别配置为 `prototype`、`active` 或 `off`，前端只消费 `GET /api/workbenches` 返回的状态；状态缺失、接口异常或真实实现未注册时必须停止加载正式功能，不能把示例数据伪装成真实结果。

真实模块按采购、研发、销售、总经办的依赖顺序分别通过独立 Issue 和 PR 接入。模块数据仍由宏昊 AI 的 FastAPI 与 SQLite 管理，但模块迁移只能新增带模块前缀的表、字段和索引，并使用独立的 `workbench_<id>_schema_version` 元数据，不提升或破坏核心 `schema_version`。因此模块回退后，核心旧版本可以忽略新增数据并继续启动；已有模块数据保留，修复后重新启用。

模块进入正式使用前必须在独立 `HONGHAO_DATA_DIR` 中影子运行，并通过业务复核、数据安全审查、代码审查和回退演练。模块需要模型、技能或工具时只能经过既有 `HarnessRuntime`，不得绕过受控工作目录、能力白名单和人工确认写入边界。

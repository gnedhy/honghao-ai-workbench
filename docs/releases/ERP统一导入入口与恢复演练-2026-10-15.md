## 入口与边界

`scripts/import_research_candidate.py::apply_candidate` 继续限定本轮 `acceptance` 数据库，拒绝正式库。共同的数据写入部分由 `scripts/release_research_import.py` 的正式入口复用，不增加对外API，不把验收库整库复制到正式环境。

正式入口分 `prepare` 和 `apply`。前者核对现役配置的生产 profile、数据目录、实际数据库环境和应用账号、有效系统管理员及当前迁移就绪；固定候选目录全部文件、来源原件、程序和构建文件哈希，生成新原生备份及可审阅计划。正常正式配置默认对应 `honghao_production` 和 `honghao_production_app`；隔离演练使用独立配置显式登记其数据库与受限账号，不能靠端口识别环境。

`apply` 要求计划 SHA256 和 `--confirm IMPORT`，重新核对身份、哈希、全表内容、附件及运行配置。持有既有服务锁和目录标记，拒绝正在运行的服务。先将备份原生恢复到独立空库和独立空目录，由既有恢复工具逐表、附件和来源路径核验，再开始目标库业务事务。恢复空库名必须以 `honghao_acceptance_erp_release_` 开头，不能是目标库或共享目标目录。

配方版本、库存、4742项成本复算、冻结成本、5名部门账号及4名总经办账号的配置、批次回执共用同一事务。操作人使用计划中明确指定的有效管理员。失败时回滚整个业务事务，核对全表恢复原状后，只删除本次新建、名称与内容哈希一致的来源文件；既有文件保持。发生中断、提交结果不明或清理核对失败时保留 `.restore-incomplete`，现有服务启动检查会拒绝启动。

批次哈希及计划、备份、操作人、时间和数量存于 `research_meta.erp_import_batches`，与业务结果同时提交。即使随后导入了其他批次，也不能重放旧批次。数据库中的持久记录是提交依据；外部回执文件写入失败不能据此推定数据库未提交，须先核对该记录，禁止直接重试。

## 经批准后的执行顺序

1. 固定已验收程序及构建，重新核对现役指针、进程所有者、数据库与导入范围，进入停写维护窗口。保留匹配版本4程序、配置、附件和当时最新的版本4原生快照，并用版本4程序恢复至新空库核验。
2. 使用迁移账号显式执行本批版本5，切回受限应用账号核验；保持服务停止。迁移不由导入工具或服务启动自动执行。后续AI功能不在本批发布范围，接续版本6—18另行验收。
3. 注入正确的 `HONGHAO_DATABASE_URL`、`HONGHAO_DATABASE_ENVIRONMENT=production`、`HONGHAO_ENVIRONMENT=production`、`HONGHAO_DATA_DIR`，用固定版本程序执行 `prepare`。此时备份为版本5、业务写入前状态；保留版本4迁移前备份。新计划的目标必须为正式库，候选SHA为本批已验收值，账号及数量须与审阅清单一致。
4. 审阅并固定新计划SHA；准备本批前缀的新空恢复库，使用迁移账号显式迁移到版本5，恢复目录保持空。仅把该空库的迁移连接注入 `HONGHAO_IMPORT_RESTORE_URL`。正式目标连接始终使用应用账号。执行 `apply`，工具自行完成真实恢复和事务导入；不要另行再次运行账号配置。
5. 核对实际回执、产品及原料数量、成本、字段、历史、账号范围和跨部门拒绝访问，保存导入后原生快照。切换现役程序、启动并验证正式HTTP登录和工作台后再开放业务；这一步不由本导入脚本执行。

命令参数示例（所有大写占位须替换为维护窗口中已核对的具体值，连接凭据不写入命令或文档）：

```powershell
python scripts/release_research_import.py prepare --active ACTIVE_JSON --candidate CANDIDATE_DIR --input-sha256 INPUT_SHA256 --actor ADMIN_ID --backup-destination BACKUP_DIR --plan NEW_PLAN_JSON
python scripts/release_research_import.py apply --plan NEW_PLAN_JSON --plan-sha256 PLAN_SHA256 --restore-data-dir EMPTY_RESTORE_DIR --receipt NEW_RECEIPT_JSON --confirm IMPORT
```

## 失败恢复

普通业务异常以本次事务回滚及全表核验为准，保留失败日志和恢复演练库；再次执行前查持久批次记录，重新准备空恢复库。禁止删除无法解释的禁止启动标记。

如果中断后不能确认结果，保持停写，先保存现场。对照备份、全表证据及 `erp_import_batches` 确认未提交或已完整提交，再决定清理标记并继续核验，或把匹配快照恢复到另一新库及新目录。回退至版本4必须使用迁移前版本4快照和程序；版本4程序不能直接打开版本5数据库。不得覆盖唯一正式库、改写迁移历史或复制验收数据库。

开放业务后如已有新报价、价格或配方变化，先保留新写入和现场，再选择补偿方案；不能直接恢复旧整库而丢失合法新数据。正式维护窗口的最新备份、正式HTTP及实际切换尚待发布阶段执行。

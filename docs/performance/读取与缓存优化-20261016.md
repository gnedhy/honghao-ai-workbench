# 工作台读取与缓存优化（隔离候选）

本轮只调整读取与展示，不改变成本计算、取价、收率、权限规则、冻结记录或数据库结构。正式服务未替换，未提交或推送。采购涨跌排行改为窄价格序列接口，销售沿用既有读取机制并验证实际组件性能，研发消除已定位的重复工作。

## 已落实的读取边界

| 入口 | 读取与复用方式 | 正确性边界 |
| --- | --- | --- |
| 采购涨跌排行 | 26 个完整批次详情请求改为一个价格序列请求，只返回价格、版本、来源日期及价格类型 | 沿用既有字段权限过滤；逐项价格与来源日期对照完整批次；不将继承快照算新报价 |
| 研发概览 | 新客户端显式请求 summary=true，历史只传趋势及相邻期比较所需字段；旧 API 表示继续兼容 | 两种表示分别使用 ETag；产品台账字段、完整成本精度不变；打开历史再读取既有冻结详情接口 |
| 走势图与排行 | 同一个已授权概览建立产品历史索引；走势图不再调用完整详情；索引随概览对象变化重建 | 不补造缺失期、不合并不同产品、不把缺价当零；日期及同日回算顺序保持 |
| 研发配方目录 | 每页 50 行，筛选后回第一页 | 全部授权目录仍可筛选和翻页，未截断数据 |
| 概览刷新 | 前台每 60 秒条件检查；窗口重新获得焦点、恢复可见、授权变动时检查；本页写入后立即检查 | 304 保留当前表示；失败不循环掩盖错误；401/403 清空数据 |
| 产品详情 | 每次验证会话、产品访问范围及数据版本，再返回精确缓存；同账号同产品请求合并 | 锁等待后再次校验；库存、配方、草稿、事件和权限变化使缓存失效；用户专属启用能力不跨账号复用 |
| 详情刷新 | ETag 条件读取；计算中 5 秒、失败待重试 30 秒；隐藏页面暂停定时请求 | 错误不能冒充成功；401/403/404 清掉旧详情；保留原草稿冲突及试算规则 |
| 服务端容量 | 概览最多 16 项且 64 MiB；详情最多 32 项且 16 MiB，LRU 淘汰 | 超大详情仍正常返回但不缓存；不持数据库连接等待合并锁；读取并发仍为 2 |
| 历史读取 | 已有历史投影时不再重复读取采购期次依据 | 保持同一事务快照及既有排序，不改变历史记录 |

## 验证证据

真实隔离副本：2,384 个产品、29 期、7,082 条产品历史。使用同一副本和相同管理员，以 FastAPI TestClient 测试真实路由/鉴权/数据库及 JSON 序列化，测试临时会话已清除；不是浏览器端到端耗时，也不是操作系统冷缓存测试。

- 采购 26 批次：完整详情合计 2,145,299 字节 → 序列 683,445 字节；同机业务层读取合计 1.15 秒 → 0.046 秒；每批价格及来源逐项一致。原请求并发执行，不能把业务层耗时合计解释为页面加速倍数。
- 概览未压缩响应：9,834,659 → 5,041,120 字节，减少约 48.7%。
- 详情 1,151,331 字节，前后内容 SHA-256 一致；缓存优化不删减详情证据。
- 初次样本中详情重复读取约 0.77–0.81 秒 → 0.23–0.25 秒；条件读取约 0.14 秒。并行回归期间复测有波动，不能将单次数字视为 SLA。
- 首次读取仍有成本：概览约 1.4–1.9 秒，详情约 1.1–1.5 秒；本轮不能宣称消除了冷启动等待。
- 合成 5,000 产品 × 30 期：历史归组旧扫描约 4,247 ms，新索引约 33 ms；150,000 条精确成本逐项一致。这是 Node 中算法对比，不是网络性能指标。
- 真实副本 2,385 个核算对象的计算输入与双成本哈希、22 个账号的数据范围，与原基线一致。
- 浏览器既有固定负载预算通过，采购 2,000 行、研发 500 行、销售 2,000 产品/4,000 成本选项，5 次样本、4 倍 CPU 降速，未放宽预算。

测试记录：扩展回归初跑 107 通过、1 项旧排队测试失败；调整该测试以适配同请求合并后，相关 17 项全部通过（含新增 8 并发详情合并）；新采购序列 API 测试通过，采购与研发分析 25 项通过，加载交互场景通过。前端质量检查 70 模块、9 项既有记录、0 新增；本次修复一个受影响 Hook 并移除对应过期基线，未放宽门禁。

本地证据目录：`C:/ProgramData/HonghaoAI/backups/inventory-details-20261016`（read-before.json、read-after.json、read-tests.log、read-recheck.log、candidate-comparison.json）。合成索引和浏览器预算收据位于 `.scratch/`。这些文件留在本机，包含真实业务的数据不进入远程仓库。

## 扩容边界与后续实现顺序（前一轮记录）

当前没有引入 Redis、跨用户浏览器持久缓存、后台预取全库或修改生产数据库。服务器缓存是可丢弃派生表示，重启或淘汰后可由正式记录重新生成。

1. **变更版本表**：当前 ETag 仍扫描相关表的 MVCC 标识。下一阶段通过事务内数据库触发器维护分域版本，覆盖 CLI、批量导入、删除、TRUNCATE、权限调整；回滚不能推进有效版本。该项涉及迁移、备份恢复及另一开发分支的迁移顺序，不能用短 TTL 代替准确失效。
2. **分页面读取**：当前概览仍携带全部台账与历史摘要。下一阶段为仪表盘、台账分页、目录和版本清单提供独立读取模型，服务端过滤排序，详情和冻结图继续按需读取；保持旧接口兼容，禁止全量拉取后仅在浏览器切页冒充服务端分页。
3. **原料穿透**：仍先读取原料目录再读详情。应补按编码查询的窄接口，同时返回该原料必需的批次继承信息，避免省略继承信息造成趋势失真。
4. **验收**：版本更新前后、同版本并发、撤权/停用/注销、失败恢复及大数据冷读分别测量；同时比较精确成本、冻结历史和可见范围。没有增长负载的实测前，不承诺任意规模保持相同延迟。

以上是前一轮留下的范围；事务标记与两类台账分页的续作结果见下节，其他边界仍保留。


## 续作：事务版本与服务端分页（隔离验收）

已在独立 PostgreSQL `inventory_detail_copy`（63519）应用迁移 0006；正式数据库和正式服务未更新。迁移前完整转储保存在本机 `before-read-versions.dump`，校验记录为 `read-versions-migration.json`。

- 25 张依赖表由数据库语句级触发器维护版本；同一事务对同表多次写入只推进一次，版本与业务写入一起提交或回滚。覆盖应用、直接 SQL、批量写入、删除及 TRUNCATE。标记放在受保护的 `honghao_meta`，应用角色仅能读取；缺标记时拒绝复用缓存。
- ETag 改为读取固定数量的版本行，不再扫描每张业务表的 `ctid/xmin`。读取版本、权限和内容仍处于同一快照，排队后重核权限。
- 新增 `/pages/products`、`/pages/formulas`，服务端完成筛选、排序、总数及分页；每页最多 200 条，默认 50 条。金额排序使用 Decimal，缺价排末尾，以产品 ID 打破同名排序并列。旧接口及完整导出保留。
- 产品成本和配方管理直接请求分页接口，不再为进入这两个页面加载整份概览。连续全量显示改为有界分页；筛选菜单来自本权限范围，跨页保留。快速切页或搜索取消旧请求；403 时清空旧结果，避免显示前一权限范围。
- 复用既有双成本及历史涨跌投影：每个数据版本和权限范围生成一次列表快照，复用受容量限制的服务端缓存。**这是服务端快照分页，不是数据库 LIMIT 分页**。冷重建仍读取该范围的列表和比较历史；仪表盘/历史概览仍使用原接口。这一限制不应包装成任意数据规模的固定延迟保证。
- 兼容修复：就绪检查支持迁移中的 `IF NOT EXISTS`，不放宽结构完整性检查。

### 实测

| 产品成本 | 2384 / 48 | 57,702 B | 1.8613 s | 0.2488–0.3045 s | 0.0938 s |

115 项成本、权限、条件读取、并发及分页回归通过；补充迁移、TRUNCATE、并发直接写入与备份恢复的 25 项测试通过。浏览器验证覆盖分页、搜索响应乱序及拒绝访问清理。前端构建、质量检查通过。证据为本机 `page-tests.log`、`page-migration-tests.log`、`pages-benchmark.json`、`candidate-comparison.json`。

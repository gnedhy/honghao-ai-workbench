# 历史增量读取设计 · 2026-10-21

本记录描述读取改造的设计与验收要求。2026-10-21 已按本设计实施隔离候选，验收状态见[增量读取隔离记录](../releases/增量读取隔离验收-2026-10-21.md)，尚未正式启用。此前存储层改造见[历史摘要精简与冻结输入共享](../releases/历史存储优化隔离验收-2026-10-21.md)。用户要求随数据增长提前设计，不再依靠逐次压缩修补。

## 改造前的现状与根因

现有事务级版本标记、ETag、同范围请求合并、有容量上限的缓存、排队后二次鉴权应继续复用。但缓存只能改善重复访问，首次加载和新增一期后的未命中仍受查询范围决定。

| 入口 | 当前实现 | 增长风险 |
| --- | --- | --- |
| 研发概览 | `ResearchStore.overview` 调用 `linked_histories`，读取可见产品的全部期次 | 首次及版本变化后仍随产品数×历史期数增长 |
| 研发列表 | `/pages/{kind}` 在未命中时重建范围内完整列表，再用 `page_rows` 分页 | 返回已分页，数据库和组装工作量尚未真正按页限制 |
| 研发详情 | `linked_histories` 重组产品全部期次的冻结内容 | 打开当前配方也承担全部历史详情成本 |
| 采购走势 | `ProcurementStore.price_series` 读取全部批次及批次投料价格 | 单个原料走势也读取其它原料和全部期次 |
| 销售历史 | `SalesStore.history` 读取本人／管理员范围全部正式记录或试算 | 报价累计后响应和浏览器筛选越来越重 |

本轮共享冻结内容解决重复存储，摘要精简减少每条读取成本；两者都没有把上述增长关系消除。因此本轮结果不能解释为已完成长期增量读取设计的实现。

## 读取边界

遵循“当前状态与历史证据分离、先鉴权后筛选分页、每次请求工作量可解释”。沿用现有业务层，不引入通用缓存框架或额外服务。

1. **概览指标**：只返回数量、待处理数、当前成本摘要与默认候选ID，不夹带产品×期次历史矩阵。默认候选继续在当前权限、选定范围内按已有规则和自然排序选择；手动选择按账号／工作台保留，失去权限时清除。
2. **列表与搜索候选**：服务端索引过滤、排序、分页，沿用默认50、上限200；页数与计数也在权限过滤之后生成。不能先加载全量再切片。列表读取最新已完成核算的投影或指针，不读取历史冻结明细。
3. **趋势**：按单一产品／原料ID、起止日期及口径查询。默认日期范围保持既有产品行为，读取量不随其它产品和范围外期次增长。缺价断点、正式／回算来源及精确值保留；不能用“上一有效值填补”伪造成连续成本。
4. **历史列表**：日期、关键词、产品／客户条件由服务端处理，按有效日期、版本、唯一ID确定稳定顺序，每页最多200条。游标携带查询条件和读取版本；范围或版本变化时从第一页重新读取，避免翻页重复／遗漏。列表只含摘要，点击一条才读取该条冻结证据。
5. **详情**：当前成本／配方与历史列表分开读取。历史详情必须用明确的记录ID和产品ID定位；复用本轮冻结内容重组，并在返回前继续执行原权限裁剪。不得因共享存储暴露引用产品的受限字段。
6. **全时间跨度**：不静默截掉历史或让单次趋势无限增长。服务端限制单次点数，超限明确要求缩小范围，完整逐期记录仍可分页追溯和受控导出。若以后需要长期图表聚合，应单独定义显示口径并保留缺价断点；聚合值不得参与成本、报价和涨跌计算。

## 增量写入与失效

优先复用既有核算事务及版本标记，不以定时过期代替正确性。

| 更新 | 应更新和失效的范围 | 不能发生 |
| --- | --- | --- |
| 原料价格／库存更新 | 直接引用及传递引用产品的成本结果、当前投影、所在部门指标和对应趋势 | 无关产品的历史详情全部重读；引用链漏算 |
| 配方／收率变更 | 本产品及受影响引用链，完成后一起切换当前版本 | 部分新成本配旧配方；中间结果被当正式成本 |
| 追加或补算历史期次 | 对应产品、日期范围的历史列表／趋势和排行区间边界 | 所有当前详情因无关旧期补算而重建；只按记录插入时间失效而漏掉旧日期 |
| 报价采用／调整／作废 | 相应客户／报价单／产品的状态、统计和历史 | 旧采用记录被覆盖而无法追溯 |
| 调整权限／归属 | 相关账号可见范围和会话缓存立即失效，排队后复核 | 依赖TTL继续返回已撤权内容；共享缓存跨范围泄漏 |

如引入按产品／部门的读取版本，它们必须与结果发布在同一数据库事务递增。缓存键包括权限范围／授权版本、数据版本、ID、日期、口径、筛选和游标；只用URL、账号或部门名均不够。不可变历史内容可以复用，但是否允许读取仍须每次实时校验。

批量核算继续使用既有冻结输入、计算与原子发布边界；只有完整一批成功，才发布新的当前指针、投影与版本。异常回滚不得留下半期统计或新版本标记。长期任务可分批准备，但不能因此改变正式成本的一致性。

缓存仍需内存容量上限与单范围合并重建。不要先预热所有用户×所有筛选组合，也不要以增大缓存掩盖全量读取。并发请求复用同一个已鉴权范围的构建结果；授权变化后不能复用之前排队的结果。

## 索引与投影

先用执行计划验证，再增加所需索引，避免给每个JSON字段建索引。候选索引方向为产品／原料ID＋有效日期＋稳定记录ID、部门范围＋默认排序键、报价所有者／客户＋创建日期＋ID。不直接照搬字段名：回算与正式记录目前日期多在JSON中，应在真正改造时迁移成可索引的生成列或维护投影。

当前状态投影必须保留精确成本及原记录指针，金额原值仍来自原核算结果；排序不得转换为浮点数。排行需要读取区间开始前的有效基线和区间结束值，不能仅对页面内或截断后的两点计算。统计可按期间增量维护，但必须保留重建途径及与冻结历史核对的方法。

## 数据增长验收

后续改造必须把以下检查纳入固定性能门禁，不能只用当前真实样本跑通一次。数据来源、机器限制、查询计划、返回量、SQL行数、计时边界及成本精度断言都要记录。

| 用例 | 数据规模 | 必须证明 |
| --- | --- | --- |
| 历史增长 | 同样2,500产品，26／130／520期 | 当前页与最近一个月单产品趋势不加载范围外历史；固定范围返回量保持有界 |
| 产品增长 | 2,500／10,000产品，固定范围与期次 | 单页／单产品读取不扫描和返回全体产品；管理员统计用聚合或受控投影 |
| 更新后首次重读 | 追加一期、补入旧日期、修改一个原料 | 正确失效、受影响引用链完整、无关详情不重建、新值一次完整可见 |
| 并发 | 1／5／20会话，管理员与多个部门 | 同范围合并、等待有界、无失败放大，记录P50／P95及最大值 |
| 权限变化 | 读取与排队过程中撤权、转部门 | 304和缓存命中前仍鉴权；403／404及范围计数正确，不返回旧范围内容 |
| 历史精度 | 多层BOM、负投料、零价、缺价及两种成本口径 | 全精度金额、来源、签名、断点与冻结明细不变 |

硬性结构断言先行：页数上限、单产品条件、范围条件、无完整BOM出现在摘要、无无限缓存。扩容样本的固定范围读取P95不得随总期数呈近似线性增长；具体毫秒上限沿用项目现有性能政策，新增指标须在相同硬件基线实测后制定，不能虚报已达标或放宽原门槛。

## 改造顺序

1. 研发概览拆出单产品趋势及历史分页，当前详情不再重组全部历史；这是本轮真实数据已证实的主要增长点。
2. 研发列表将已有接口分页下推到数据库／当前状态投影，兼容现有筛选、排序、权限、编辑草稿及返回定位。
3. 采购单原料走势和销售历史按相同边界迁移；统一读取契约与共享控件，不共享权限结果。
4. 在上述读取边界正确之后，按实测增加细粒度失效和必要的增量统计；每步必须通过增长、更新和撤权用例，不能以缓存命中成绩代替首次／更新重读成绩。

以上为接续实施边界，本轮不擅自加入新缓存服务、不改变正式成本定义、不删除旧期次，也不把“已设计”记成“已发布”。

# 扩容与多人读取隔离测试（2026-10-16）

结论：两档测试的精确成本、事务更新可见性和部门权限通过；分页仍可用，全量看板和批量重算有明显扩容瓶颈。本轮仅操作专用 `honghao_test` 数据库；正式服务、正式库、隔离预览业务数据均未用于造数。

## 测量范围

- 新增 2,500 / 10,000 个合成产品，分属两个研发部门；沿用真实 PostgreSQL、鉴权、缓存、成本事件和计算实现。
- 每个合成产品是一条原料投料、80% 收率。先运行三次真实价格更新和成本重算，生成三期记录，再进行第四次更新。保留原测试夹具的跨部门配方引用。
- 8 个不同账号，每波 16 个分页请求；全量看板每波 4 个请求。另测管理员全部门首次读取。
- 首次表示服务器对应读取模型缓存为空，数据库和操作系统缓存未清空。使用 FastAPI ASGI 路由及真实数据库，计入鉴权、等待、读取、计算投影与 JSON 序列化；不是浏览器渲染或真实网络端到端压测。
- 原有读取并发限制、连接池、缓存容量未放宽。扩容测试为显式 opt-in，不加入普通回归的默认耗时。

10,000 档管理员首次分页 2.472 秒；首次全量看板 3.594 秒、20,570,994 字节。三次初始批量成本重算分别 23.72、35.73、36.62 秒；第四次重算与并发读取一起完成约 35.00 秒。2,500 档对应批量重算约 2.58–3.14 秒，第四次读写并行约 3.56 秒。

## 发现与修复

更新后，同一部门的不同账号原先会同时构建相同快照：2,500 档两个范围共构建 4 次，10,000 档共 3 次。分页合并锁改用权限范围及列表类型；缓存读取前仍重新核对当前账号、会话与部门权限。修复后两个范围共 2 次构建，缓存命中时 0 次，没有删除权限检查或增加并发上限。

定向回归 15 项通过（含新增不同账号同范围只构建一次测试）；两档扩容测试通过。一次提前启动的回归遇到专用测试库互斥锁超时，没有进入测试；保留失败日志，待扩容结束后串行重跑通过，未放宽锁超时。

## 正确性核对

- 合成行情价格从 32 更新为 33，最新优先精确成本从 40 变为 41.25；库存优先成本保持原值，逐项使用 Decimal 比较。
- 全量看板检查两部门所有合成产品；分页检查返回条目、部门归属及范围总数。
- 重算期间 16 个读取全部返回更新中状态及旧的完整成本；完成后旧 ETag 得到新响应、新成本，随后未变化读取返回 304。
- 本部门响应不包含另一部门的私有字段；暖缓存后撤销部门，结果清空；越部门详情返回 404；撤销研发权限后返回 403。

## 后续重点与边界

优先缩小看板的全量历史与产品载荷，改为服务端聚合和按需趋势；其次单独分析批量重算增长，避免每个产品重复构造整张配方图。当前没有持久化数据库分页读模型，冷快照仍随范围和历史增长。

本测试只覆盖单投料合成产品、三至四期成本历史，不能推断复杂多层 BOM、几十期全量历史或更高并发的上限。未跑完整发布门禁，未提交推送，也未更新正式服务。

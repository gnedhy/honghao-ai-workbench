# PR 检查分流

按实际差异判断影响，不依赖 PR 标题或作者勾选。

| 改动 | 必要检查 |
| --- | --- |
| 纯文案、说明文档 | 格式、前端规范、类型检查与构建 |
| LOGO、favicon、CSS、静态布局 | 前端规范、类型与构建、前端单元测试和实际界面消费者；不跑 API 全量、数据库恢复与性能压测 |
| 分流、工作流及浏览器性能判定机制 | 对应分流/性能回归及 CI 自身测试；不触发业务 API 全量 |
| 成本、权限、数据库、请求、事件处理、动态数值、依赖或其他未知改动 | 完整检查 |

混合业务改动以完整检查为准。界面判断使用语法树保留函数、计算、事件、输入状态和动态数值；只忽略静态视觉节点、文字、视觉属性与图标。不能通过 presentation 声明使业务修改降级。语法解析失败、业务代码新增或删除仍走完整检查。

浏览器耗时在目标值以上 10% 以内且绝对超出不超过 50 ms 时警告，超过容差失败；原始测量与目标仍保留。请求数、SQL 次数、体积、数据精度、权限及样本完整性没有容差。例：翻页目标 150 ms，154.3 ms 警告，超过 165 ms 失败。

分支保护仍要求 frontend 和 full；full 汇总实际所需检查，不代表所有改动都执行全量。分类失败、取消或必要检查失败均不可放行。PR 通过后合并不再重复触发 main push 检查；定时巡检和手动触发仍执行全量。

本次已验证实际品牌/登录改动进入 ui，逻辑与权限修改进入 full。实现入口为 `.github/workflows/frontend-checks.yml`、`scripts/ci/change-scope.mjs` 和 `scripts/performance-budget.mjs`。

# PR 检查分流

PR 和 main 推送按实际差异自动分类，不依赖 PR 标题或作者勾选。

- 纯说明文档、TSX 静态文字修改，以及无属性、无动态表达式的说明段落删除：运行分流回归、差异格式检查、前端规范检查、类型检查和构建；不启动 PostgreSQL、不跑完整 API、浏览器、性能与依赖审计。
- 成本、权限、数据库、请求、事件处理、动态内容、样式、依赖、测试、CI 配置和其他无法明确识别的改动：保留原完整检查。
- 混合改动按完整检查处理。定时巡检、手动触发和空差异也运行完整检查。

静态文字判定使用语法树比较，保留计算表达式、条件、属性、引用及函数；不是仅按文件名判定。新增 presentation 声明可以随文案提交，但声明不能使业务修改降级。代码文件新增、删除或解析失败不进入短流程。

分支保护仍要求 `frontend` 和 `full`。`full` 汇总分类与实际检查结果；分类失败、取消或必要检查未通过时不能放行。短流程中的 `full` 表示所需检查通过，不代表执行过全部业务测试。

涉及检查机制本身的本次变更仍按完整流程验收；不手动重跑同一提交已经通过的检查。实现入口：`.github/workflows/frontend-checks.yml`、`scripts/ci/change-scope.mjs`；定向回归：`node --test scripts/ci/change-scope.test.mjs`。

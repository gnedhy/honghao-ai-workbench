# 开发协作与可选 Skill

本页适用于人工开发和不同 AI 工具。协作者可以使用自己的开发流程；下列 Skill 是可选方法，不是项目依赖，也不是必须逐项执行的清单。没有安装这些 Skill 不阻塞开发，不要求复制维护者的全局配置、个人知识库或素材库。

## 必须遵守与可以替换的部分

| 类别 | 要求 |
| --- | --- |
| 项目范围与业务定义 | 遵守 [项目规则](../../AGENTS.md)、CONTEXT 对应章节及相关 ADR；业务口径变化先明确决定并同步记录 |
| 界面与公共能力 | 遵守 DESIGN 与组件约定，复用现有实现；共享组件修改验证受影响消费者 |
| 数据与环境 | 按运行维护文档使用独立开发/测试数据库、附件目录和端口；保护正式数据与恢复材料 |
| 完成与交付 | 完成已确认范围、相应测试、缺陷修复和文档同步；交付说明改动、验证证据及未决问题 |
| 授权 | 按当前任务和项目要求处理业务写入、正式发布、知识写入、提交、推送及清场；拉取仓库或拥有工具不构成操作授权 |
| 可替换的方法 | 编辑器、模型、Skill、任务拆分、TDD、人工或 AI 审查均可按任务选择；结果须满足上述要求 |

具体规范按根 AGENTS 的任务导航读取，本页不另建业务或发布规则。项目规则适用于所有协作者；工具不会自动读取 AGENTS 时，由开发者主动阅读并向所用工具提供相关约束。

## 首次拉取后的指引

1. 阅读 [README](../../README.md)、[项目规则](../../AGENTS.md)及[当前交接](../当前交接.md)，确认当前源码、已完成工作和本次任务范围。交接中的生产路径与历史授权只供识别，不是本机启动配置。
2. 按 README 和[运行与维护](../运行与维护.md)准备项目依赖与隔离环境。账号、数据、凭据以及维护者的全局 Skill 不随 Git 拉取；使用本人的开发配置和测试数据。
3. 根据任务读取业务、设计和组件资料，再按下面的通用流程开发。普通功能开发无需阅读或复跑维护者的 Skill 全量验证；验证文档中 `.scratch` 链接是本机历史证据，拉取后缺失不阻塞开发。

## 不依赖 Skill 的开发流程

| 阶段 | 应完成的工作 |
| --- | --- |
| 明确任务 | 记录目标、范围和验收条件；已有明确决定直接沿用，只有关键未决项才补充确认 |
| 定位实现 | 查相关业务规则、调用入口和消费者；复用现有组件及测试入口 |
| 实现与验证 | 在隔离环境实现，按影响测试并修复问题；文案修改只做对应检查，共享改动覆盖实际消费者，模块正式启用完成现有门禁 |
| 审查与交付 | 对照需求和项目规范检查结果，数据安全另行核对；同步必要文档，说明证据、限制和恢复方式（涉及发布时） |
| 提交与发布 | 按当前授权提交、推送或准备可审阅候选；正式替换遵循项目发布与恢复要求 |

流程可合并、迭代或采用团队自己的方式，以上适用的完成条件仍需满足。未决问题只阻塞依赖它的部分，独立且已授权的工作可以继续。

## 使用 Skill 时的可选映射

| 任务 | 可选 Skill | 预期结果 |
| --- | --- | --- |
| 已明确的功能 | implement；按需要使用 tdd，沿用已确认测试边界 | 完成实现、受影响验证及规格/规范审查 |
| 关键需求不明 | grilling；需同时明确业务概念时用 grill-with-docs；缺外部事实用 research | 决定充分后固化规格，不重复访谈 |
| 信息在业务人员手中 | to-questionnaire | 问卷返回后补齐规格，未决信息只阻塞依赖部分 |
| 业务定义变化 | domain-modeling | 明确概念及 ADR，再回到规格或实现 |
| 实现边界不清 | codebase-design | 确定接口与测试入口，沿用项目业务词汇 |
| 已有界面完善 | impeccable；apple-design 和动效能力辅助 | 复用公共组件，在隔离环境检查实际消费者 |
| 界面方案比较 | 明确调用 prototype 后探索 | 用户选定方案后才集成，不重新设计范围外页面 |
| 复杂、反复、根因不明故障 | diagnosing-bugs | 有效复现、根因修复、回归与按影响审查 |
| 交付审查 | code-review；过度设计专项用 ponytail-review | 分开报告规格与规范问题，数据安全另行审查 |
| 架构专项改进 | improve-codebase-architecture | 提出有证据的候选，选定后设计和实施 |
| 接续工作 | handoff | 引用当前交接、规格、差异及未完成事项 |
| 文档与事实收尾 | neat-freak；写代理文档时用 writing-for-agents | 核对本轮一致性，清场仍遵循独立授权 |

## 专项能力

- leader 把复杂目标整理为可执行任务书，复用已有规格，不重做同一轮需求访谈。
- loop-me 设计业务工作流规格，不是开发 Agent 的无限循环执行器，也不自动启用应用中的自动化模块。
- research 查一级来源；hv-analysis 用于需要横纵比较的系统研究。OpenAI 产品问题优先使用 OpenAI Docs。
- animation-vocabulary 识别术语；find-animation-opportunities 发现机会；animate 实现；review-animations 审查已有动效；improve-animations 做专项改进。按实际问题选择，不全部叠加。
- shadcn 与 pick-ui-library 用于对应组件或真实依赖缺口；先查项目公共组件和现有依赖，不因工具可用引入另一套 UI 体系。
- manage-gnedhy-kb 提供相关经验并按授权入库；manage-eagle-library 处理素材；storage-analyzer 处理磁盘空间。不作为普通开发的固定前置。

## 阶段交接与授权

使用多个 Skill 时，同一阶段选一个主导流程，其他 Skill 完成专项职责。每次切换沿用目标、范围、已确认决定、验收条件、证据与未决问题，以已有规格、Issue、ADR 或当前交接的链接传递；不另建一套事实副本。

用户中途纠正时，只更新受影响决定，保留有效成果。仅询问影响结果且无法从现有资料取得的信息；等待某项输入时继续独立且已授权的准备。实现后持续完成隔离运行、验证和修复，不在首次代码产出时提前结束。

访谈、设计方向和架构候选选择保留实际决策价值；同一对象、范围及有效时点内已明确批准的阶段不重开。Skill 的可用性不扩大业务数据、外部发布、提交、推送、知识写入和清场授权。

handoff 的临时包只引用项目现役资料与未完成工作；neat-freak 核对事实一致性；知识库 Skill 负责经授权的入库，三者不互相代替。

## 当前宿主与并行

区分磁盘安装、会话可见和显式调用策略。明确调用或已进入的合法组合需要某 Skill 时，使用当前宿主支持的读取/调用方式；文中的“Skill tool”不是必须存在的工具名。保留显式调用限制，不因发现文件就擅自启用或修改配置。

Skill 确实不可用时，说明缺少的能力，用已授权的现有工具完成可执行部分；不自动安装替代品，也不声称执行过缺失流程。

独立研究或审查按当前平台权限与项目并行规则委派，给出输入、输出和完成标准。共享文件修改、同一测试库及发布统一协调；无并行能力时标明串行替代，不能宣称独立双人审查已完成。

## 模型变化与复验

业务契约、权限和验收标准长期保留；提问、拆分、并行和检查范围根据实际任务调整，不固定模型名、推理档位或 Agent 数量。维护这套 Skill 的使用者升级模型或宿主时，可先按 [验证记录](skill-validation.md)复跑核心组合，发现实际退化后只修相关规则，并复验受影响路径。

本轮验证日期：2026-09-15。模型及宿主是验证证据，不是使用限制；具体覆盖、失败和未验证项统一记录在验证文档。

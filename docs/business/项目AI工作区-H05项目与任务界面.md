# H05 项目与连续任务界面

2026-10-06；基线 `4bd8d5ba6dcdeeb7b7c71416672dc51d2e0c2fc8`，任务分支 `codex/h05-project-task-ui`，对应 [#77](https://github.com/gnedhy/honghao-ai-workbench/issues/77)。沿用 [H02 交互](项目AI工作区-领域与交互.md)、[H03 数据合同](项目AI工作区-H03数据与权限.md)与 [H04 接入](项目AI工作区-H04运行接入.md)。界面扩展既有聊天／任务；没有新职能工作台、组件库、运行时注册或正式启用。

## 已确认界面与职责

- 保留现有浅灰侧栏、白色正文、输入区、分段选择和抽屉。侧栏项目展开显示实际会话；项目菜单只有查看详情／新建会话等真实动作。移除无置顶能力的占位。项目详情提供名称、本人归属、实际会话／任务及更名；资料、规则与技能由 H06／H07 实现后加入，不放空功能标签。
- 新聊天维持默认工作意图。聊天／工作转换经过所属草稿／忙碌检查，保留布局切换和后台刷新时的输入；不按模式重建输入根。现有任务的项目冻结来源单独展示，不能与新会话默认项目混淆。多任务历史须明确选择 taskId；任务看板、搜索和上下文返回都传明确任务。
- 提交先取得真实消息接受回执，再幂等启动该消息的 H04 运行。启动未配置或失败时保留已接受消息及待执行入口；不称模型已完成，不自动排队或重复执行已终结输入。新的独立目标另开会话，同任务补充只增加消息／运行。
- 正文按原始换行显示实际用户／助手文本，执行状态贴近对应输入，正在运行的输出不与已保存助手消息重复。待执行旧消息可明确启动；重新进入优先对账该会话实际活动运行，不用最新用户消息推断。运行中可编辑下一草稿，发送和模式切换等待终态；停止请求只表示已接受，确认中保留正文和草稿。
- 任务看板保留现有表格／搜索结构，真实状态与项目来源可读；打开任务进入来源会话并指定 taskId。运行列表／详情复用菜单和 Drawer，含真实状态、时间、正文／停止说明及已报告用量；没有记录、读取失败、刷新失败分别展示。撤下虚假工作流页面、技能／工作流搜索结果、知识引用、模型切换、目录授权、文件选择及样本统计；原源码与历史数据保留。

App 只保留身份、选中对象和公共导航协调。聊天／项目业务 Hook 管理列表、消息读取、项目创建／保存、草稿、稳定提交键和接受／启动恢复；任务所属 Hook 管理运行读取和取消请求。Composer、Sidebar、Drawer 等公共组件只呈现受控值、反馈和操作提议。

## 保存、并发与权限

首次项目创建增加可选稳定 submission_key；旧 title-only 调用继续兼容。服务端按 owner＋key 去重，比较原创建名称，改名后同创建请求仍返回同一项目；同键异名称冲突。新增 0008 连续迁移（core schema8）保留旧表和摘要，旧 SQLite 明确排除新创建元数据；快照表摘要将原生 UUID 规范化为字符串，创建回执与改名结果在恢复后继续去重。不通过名字猜测断线创建结果，不覆盖合法项目。更名沿用 H03 revision，冲突重新读取但保留提议，用户核对后明确重试。

消息草稿在本人／当前业务对象的内存中维护，trim 后提交保留原快照和稳定键。接受响应未知时先用同一原请求对账，不能因编辑草稿而丢弃原请求或重复建任务；已接受消息并入列表，只清除仍匹配本次提交的输入，不抹掉发送期间的后续编辑。执行启动结果未知用 H04 GET 对账；页面重连不自动 POST 新运行。

读取按 owner／对象／请求代次取消和丢弃旧回包，合并 immutable message ID 与较高 revision，不用旧整表覆盖新提交。模块关闭、旧无主只读、身份失效与普通读取失败分别处理；已知 tasks 关闭时不请求其接口；列表或运行读取 403 仅清理任务能力，不能抹掉可用聊天。迟到工作接受回执也按当前任务能力失效，不启动执行。旧无主记录仅管理员只读，不提供提交／执行／更名。

草稿 dirty、项目保存／消息接受／启动停止回执 busy 接入 useUnsavedChanges／confirmWorkbenchLeave。侧栏、新聊天、项目／会话／任务、搜索、模式、项目关联、注销、抽屉关闭与浏览器出口按实际对象检查；取消保留输入，批准放弃后才继续原动作。布局开合不丢弃草稿。服务器执行本身不阻止离开，不按页面卸载取消运行；注销／撤权清空该身份的正文、草稿、订阅与待决操作，不等待 dirty 确认。AI 请求携带所属登录身份的 X-Workspace-Actor；服务器在已认证 cookie 上比对，跨标签切换账号时先拒绝旧页面请求，不把旧草稿接受给新账号，也不回填新账号数据。旧请求不带该可选头继续兼容；该头不是授权凭据。失效回调只清理并重新读取身份，不发送可能注销新账号的自动 logout。

## 接口与验证

沿用项目、会话、接受、任务和运行接口，增加本人会话的只读 active-execution 对账，返回已有 H04 安全 DTO；不转发原生 RPC。任务运行响应只增实际正文／阶段／已报告统计等安全字段，旧字段保留；不返回原生上下文、目录、环境或凭据。

实际 App＋API＋隔离 PG 验证：项目创建失败／响应丢失去重及更名冲突；聊天无任务、工作连续任务、明确多任务选择和冻结归属；接受与启动分阶段失败／旧回包；真实运行历史、断线／停止／重新进入活动运行；dirty／busy 的可达出口、撤权清理；关闭任务模块和管理员无主只读。故障注入的 stdio／模型／OS 边界明确为模拟。

1440／1024／390 视口检查实际布局、键盘、正文换行、菜单／抽屉、空／错误／刷新状态、无横向溢出及控制台健康。Browser plugin 未列入本会话，复用现有 Playwright 实跑入口；不安装新依赖。新增用例、实际消费者、变更声明和保护清单一起审查；完整 verifier 保留所有原样本与三类性能预算，当前候选 frontend/full CI 通过后才合入功能集成分支。

交付另起独立、持续的隔离预览数据／账号／目录，与测试 fixture 和正式服务分开；本地 Ubuntu 用固定真实内核及合成资料核对新消费者，模型网络另记。完成后在 Codex 打开界面供用户试用。文件／成果、规则／技能仍由 H06／H07 开放；企业目标身份与完整正式候选由 H12／H13 验收，不向 main 合并、部署或启用本项。

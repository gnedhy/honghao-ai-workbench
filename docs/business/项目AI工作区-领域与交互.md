H02 设计基线：2026-10-06，集成分支 `7708ba097f92616f6d73b9bf986ee10be4a4b646`，对应 [H02 #74](https://github.com/gnedhy/honghao-ai-workbench/issues/74)。本页是后续规格与验收的产品约定，不表示界面、接口或模块已启用。术语以 [CONTEXT](../../CONTEXT.md) 为准；旧约定替代见 [ADR-0011](../adr/0011-项目AI工作区与Codex运行边界.md)。

## 范围和模块

以实名员工的个人项目组织会话、连续任务、资料、项目规则和技能。保留采购、研发、销售工作台，增强既有聊天及任务模块；不建立第四个职能工作台或运行时注册框架。

| 能力 | 首期入口及边界 |
| --- | --- |
| 新聊天、项目与会话 | `chat` 内；项目可选，所有者私有，新聊天默认沿用现有“工作”意图 |
| 持续执行与运行记录 | `tasks` 内；工作依赖聊天和任务均可用，聊天问答本身不创建任务 |
| 项目资料与成果 | 聊天／项目内选取文件或文件夹上传、任务工作副本、指定版本下载；知识库无需启用 |
| 项目规则和技能 | 项目详情与工作输入菜单；通用／项目技能真实发现和显式调用，不为旧路由启用 `automation` |
| 业务查询 | 受控只读入口，逐次验证所属采购、研发或销售权限，不产生业务写权限 |
| 指定成果分享 | H10 分享指定版本给指定员工；不产生项目成员、目录或其他成果的访问权 |
| 暂缓 | H09 本地目录授权；不作为当前 H12 前置，上传下载完善后再评估 |
| 关闭／后续评估 | 知识库、工作流入口关闭；多 Agent、自动调度和企业插件目录仅保留评估 Issue |

`chat`、`tasks` 的启动状态和使用授权分别检查；任务模块不可用时，“工作”操作说明原因，不能提交后假装执行。模块关闭、管理员保存待生效设置和内核不可用是不同状态。源码合并、部署及正式启用继续分别记录。

## 页面和操作

1. 侧栏保留“新聊天”“任务看板”和项目分组。项目展开显示相关会话；项目更多菜单进入详情抽屉，包含资料、规则、技能。没有真实置顶能力时不显示“暂无置顶会话”等占位。
2. 点“新聊天”只建立本次草稿；选项目提供后续创建的默认上下文。创建项目由本人明确提交名称，保存成功后才加入侧栏，失败保留名称，不提前收起输入。
3. 新聊天维持现有空状态和 Composer。已有会话展示用户消息、实际助手正文、执行状态及成果卡片；顶部显示会话、所选任务及其项目归属，不能让任务与默认项目混淆。
4. 任务看板按本人授权记录展示状态、项目和最近真实运行。打开任务定位来源会话及明确 taskId；运行详情与成果使用既有抽屉。没有运行则显示“尚未运行”，读取失败不显示为空。
5. 项目资料显示原件版本、上传状态和选入本次执行的标记；成果卡片显示版本、生成状态及下载动作。项目规则和技能保存均有版本与冲突状态，不能仅切换前端勾选态表示生效。

视觉和响应式约定见 [surface](../../.impeccable/surfaces/project-ai-workspace.md)。公共确认、退出、菜单、抽屉、加载和错误状态复用[组件索引](../components.md)；权限、请求、输入和执行状态不放入公共组件。

## 意图与任务连续性

聊天对消息及明确选取的只读上下文问答，不创建持久任务，也不执行技能、业务工具或写工作副本。工作承载受控工具、文件处理和交付；需要执行能力时由用户明确切换，不根据模型文字自动升级意图。计划可作为工作内容展示，首期撤下没有独立权限与运行验证的“计划模式”开关。

新会话首次工作提交建立任务；继续、补充、修改或对成果提出后续要求，都沿用所选任务。已完成、失败或已停止的任务可以明确继续，新增一次运行并保留旧运行与成果。新独立目标点“新聊天”，不按每条消息创建任务。首期每个新工作会话使用一个当前任务；旧会话已有多个任务时，保留全部记录并明确选择继续对象，不自动合并。

同一任务同时只有一次活动运行。运行中允许编辑下一条本地草稿，暂不发送第二条运行请求；可点“停止”，等服务端确认结束后继续。首期不展示未验证的实时插话、并行运行或自动排队能力。改变意图不修改已有运行；活动运行结束前不切换当前执行意图。

当前项目只影响新建默认值。任务的所有者、来源会话和项目关联创建后冻结；会话重关联不搬移旧任务或文件。重关联前经过退出／忙碌检查，保存失败保留原归属；以后继续旧任务仍显示其原项目。不同项目的附件、规则、技能不因切换自动携带。

一次消息提交具有稳定提交键；因响应丢失而重试先查询确认，再复用同键。同键不同内容、意图、目标任务或附件版本必须冲突；明确编辑或开始新一轮工作才生成新键。服务端接受消息不等于模型完成，助手正文失败不抹掉已持久化消息。

## 状态和恢复

下表定义产品含义；H03 固化接口枚举与事务，H04 验证内核事件映射，不从模型正文推测状态。

| 状态 | 真实依据与可用动作 |
| --- | --- |
| 待执行 | 工作消息及任务已持久化，尚未开始；不展示运行耗时或已完成 |
| 执行中 | 服务端确认本次运行已开始；可停止，页面离开不隐式取消 |
| 等待补充／确认 | 明确的等待事件及目标；补充或确认参与同一任务，确认只作用于指定目标版本 |
| 已完成 | 服务端确认本次目标完成；成果生成和正式业务应用分别显示，用户可以继续 |
| 已停止 | 明确停止并获得服务端回执；本次运行中断，消息和已保存成果保留，可继续任务，不声称恢复旧运行指令位置 |
| 失败 | 记录失败阶段、可处理说明及重试入口；重试形成新运行，保留原失败证据 |
| 执行受阻 | 权限、内核、预算或依赖阻断；先解决原因再由用户继续，不自动放宽权限或无限重试 |
| 状态确认中（页面状态） | 断线、停止请求或提交结果尚未确认；先对账，不能本地宣布完成／停止或创建重复运行 |

浏览器断线只停止订阅；重新进入以 taskId/runId 和已确认事件位置恢复显示并去重。控制器重启后先核对持久记录与内核，原运行无法恢复时明确记为中断并允许新运行继续，不能仍挂“执行中”或假造成功。正文的部分回复保留并标明中断；未保存临时产物不作为可下载成果。内核会话可因权限／配置变化重建，产品任务 ID 保持；不能仅隐藏页面而继续重放已失权的资料。

停止、下载、上传、修改项目规则都由各自业务状态驱动。运行忙碌与页面忙碌分开：服务器执行中本身不阻止离开；用户在上传、保存或提交接受状态尚未确认时，复用 busy 拒绝离开并给出本地原因。停止请求未确认时拒绝重复提交，状态重查入口仍可用。

## 草稿、身份与出口

| 对象／事件 | 保留、失效和清理 |
| --- | --- |
| 消息、待选文件、本次技能、规则未保存编辑 | 按用户与业务对象保存本次本地草稿；dirty 参与所有可达出口。仅切换布局、后台刷新或同用户资料变化不重置 |
| 上传和保存 | busy 期间阻止导航；失败保留输入及逐文件结果。回包只更新对应用户、对象和草稿版本，不覆盖后续输入 |
| 已上传原件、已保存成果和提交记录 | 是服务器持久记录；取消本地草稿或卸载页面不删除。未绑定资料的保留／清理由 H06 明确专用边界，不以页面卸载清场 |
| 注销／用户身份变化 | 清空该身份的浏览器草稿、文件引用、正文、订阅和缓存；旧请求回包不能进入新账号。服务器任务不因浏览器注销取消，仍按原账号实际授权检查执行 |
| 停用账号／撤销 AI 使用权 | 服务端阻断后续模型、工具与文件动作并收敛活动运行；浏览器清除失去访问权的内容，持久审计与合法成果保留 |
| 撤销某业务读取权 | 后续该业务工具调用立即拒绝；相关回复、成果、分享及模型上下文重放重新校验来源约束，失权内容遮蔽并从缓存剔除，持久记录保留。无关的私有资料与成果不删除，不能借旧回复或成果绕过撤权 |
| 页面卸载／更换对象 | 释放订阅、读取请求、监听、计时器和待决确认；不清除服务器合法记录，不按 mode、布局或刷新给编辑根随意更换 key |

退出覆盖侧栏、新聊天、项目／会话／任务切换、全局搜索跳转、模式／项目变更、抽屉关闭、返回、Esc、注销及刷新／关页。业务草稿通过 `useUnsavedChanges` 和 `confirmWorkbenchLeave` 的通用事件参与等待；取消退出保留输入，批准放弃才执行原导航，beforeunload 保护浏览器出口。撤权和身份失效的安全清理不被 dirty 确认阻挡。

## 文件／文件夹上传和成果下载

文件选择器支持明确选取单个／多个文件，以及浏览器支持的文件夹选取；只导入确认列表中的文件。浏览器不支持文件夹选取时保留多文件入口。目录相对路径仅用于展示和受控导入，不能成为服务器任意路径；空目录不作为本期成果，也不扫描其他本地目录。

| 阶段 | 用户可见状态与约束 |
| --- | --- |
| 选取 | 待上传清单可移除；显示相对路径、文件数量与大小。不读取完整本地绝对路径，不把文件名 AGENTS.md 或 SKILL.md 当成项目配置 |
| 校验与上传 | H06 服务端白名单、单文件/批次总量、文件数与路径校验；页面使用同一实际限制。上传逐文件留结果，未通过文件不进入模型，不能假装整批成功 |
| 部分失败／取消 | 已保存原件保留；失败项可明确重试，去重不误生成新版本；未完成项不用于执行，模型提交前明确选定已上传版本 |
| 原件与副本 | 原件快照不可覆盖；重复内容与重名需给出结果或显式追加版本／更名，不静默覆盖。工作运行只写受控副本，不改员工电脑文件或采购、研发、销售数据 |
| 成果 | 生成与格式核验通过后才发布下载版本；失败或半成品不显示“已生成”。指定版本下载与分享不因新版本出现而切换目标 |
| 下载 | 每次校验身份、所有者/分享及来源授权。页面显示“下载已开始”，不声称文件已保存到某本地目录；失败可重试，同一成果不因重试重新生成 |

新会话尚未提交时，上传资料以本人私有待关联记录保存；消息接受后再绑定来源对象。首期不自动把整个项目资料发给模型，员工为本次执行明确选择资料。类型、配额、暂存清理和大文件处理由 H06 规格及性能实测确定；PDF 解析能力在既定依赖升级和审计通过后才可开放。Word／Excel 的实际支持范围与格式核验在 H06 定稿，不展示未实现的格式能力。

H06 需在当前 HTTP、实际 Chrome／Edge 中验证选取上传及下载；本期不调用目录持续授权或本地写文件接口，不要求先部署 HTTPS 才能完成该闭环。H09 重新评估时再验证 HTTPS、目录权限、失效、冲突和本地写入 busy；不能把上传目录误称为持续关联。

## 项目规则和技能

项目规则用明确的规则编辑入口管理，交付要求可涵盖语言、格式、来源、修改范围和验证步骤；保留 AGENTS.md 语义。用户普通上传的资料始终是数据，不自动载入为规则。规则是执行约束，平台权限、文件边界、工具白名单和人工写入确认优先，项目规则不能授权外部发送或业务写入。

规则／技能保存有版本冲突检查；当前运行采用启动时快照直至结束，下一次运行使用最新已保存、可用版本，并展示版本变化。安全撤权始终立即检查，不因启动快照保留旧权限。H04/H07 要验证配置变化后上下文重建／内核会话处理，不能让旧规则或缓存技能继续被误称为当前版本。

通用技能来自受控发布来源，项目技能由所有者在所属项目明确添加及管理。工作输入菜单只显示有权使用且依赖可用的真实技能；首期支持显式选择技能，选择不等于真实调用。记录本次实际提供的版本与执行证据，没有加载／调用依据不显示“调用成功”或伪造统计。

技能只能使用本次允许的工具和资料；依赖使用平台受控环境，不按上传内容自动安装包、联网下载或执行未审阅脚本。缺失依赖阻断该调用并说明原因，不静默忽略所选技能。H07 调整技能接口和搜索、输入菜单的实际消费者，automation 继续关闭，workflow 编排、插件市场及多 Agent 控件不进入首期。

## H02 场景审查及后续验收

以下是后续必须实现的业务场景，H02 仅做语义走查，不冒充运行测试：

| 场景 | 预期结果 | 负责阶段 |
| --- | --- | --- |
| 首次工作、补充、完成后修改成果 | 一次任务创建、多次运行；旧成果和运行保留 | H03—H05 |
| 响应丢失、双击、同键改内容 | 对账与幂等；不创建重复消息/任务/运行，不同内容冲突 | H03/H04 |
| 旧会话多个任务／会话改项目 | 明确继续对象；历史不合并、任务归属不迁移 | H03/H05 |
| 两员工访问相同 ID、管理员进入私有项目 | 所有权与使用授权独立检查；管理员不因配置权自动读私有正文 | H03/H12 |
| 旧记录所有者未知 | 不猜测或默认分给当前账号；H03 明确归属映射或隔离保留，再开放读取 | H03 |
| 上传、保存时切页／关闭；仅后台执行时离开 | busy 阻断本地未完成操作，dirty 可取消；后台任务不隐式取消 | H05/H06 |
| 身份更换、撤权、旧请求回包 | 清除失权内容并丢弃旧回包；工具和下载再校验，合法成果留存 | H03—H08/H10 |
| 断线、停止结果未知、控制器重启 | 原任务对账、去重、真实中断/恢复，不以页面状态伪造执行结果 | H04/H12 |
| 文件夹部分失败、重名、穿越、错误格式 | 已保存与未完成分开，原件不可覆盖，越界拒绝且可安全重试 | H06 |
| 下载旧版本、生成失败、下载重试 | 版本稳定，未验证成果不可下载，下载重试不再次生成 | H06/H10 |

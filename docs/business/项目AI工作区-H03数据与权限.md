# H03 数据、接口与权限

2026-10-06；基线为 H02 集成提交 `31d646f70ea9f1b333e1b5fd9922467e8e9f0bf5`，任务 [#75](https://github.com/gnedhy/honghao-ai-workbench/issues/75)。本页固化 H03 实现合同，产品语义沿用[领域与交互](项目AI工作区-领域与交互.md)。模块尚未正式启用，迁移、代码、部署和启用分别验收。

## 所有者和使用授权

新增账号 `ai_enabled`，默认关闭，由既有管理员账号接口和授权编辑入口维护。个人 AI 使用条件为 `is_active AND (is_system_admin OR ai_enabled)`；全局模块关闭时仍阻断接口。系统管理员可使用本人 AI 工作区、维护配置及只读查看无主历史；配置身份不允许读取其他员工的私有内容。员工使用权不继承采购、研发、销售或知识权限，不新增业务权限等级或权限框架。

项目、会话、消息、任务、运行的 `owner_id` 取服务端登录身份，客户端不能提供或更改。列举、ID 查询、关联、修改和幂等回放均校验当前身份和所有者；不可见对象统一不暴露详情。写事务复用现有序列化事务，授权变更与提交共用事务保护；服务端控制器使用账号 ID 时也重新校验账号有效和 AI 使用权。

账号停用、使用权撤销沿用既有会话撤销机制，旧会话不可继续访问；H04 每次模型／工具操作再次检查当前权限，H08/H10 处理业务来源约束。读取与写入的资源规则不因管理员配置身份放宽。

旧无主记录 owner 保持 NULL，管理员可只读查看，员工不可见；禁止编辑、关联到新私有对象、提交新工作或执行。仅明确的历史 `message_id` 关系迁入消息任务关联，不合并旧任务、不推断创建者。正式认领必须先审阅归属映射；本项不自动认领或在正式库写入测试。

## 数据迁移

增加连续的 `0005_ai_workspace.sql`，不改旧迁移摘要；schema 业务版本升级为 6，identity 版本升级为 7。数据库仍由迁移账号显式升级，应用账号没有 DDL，未迁移时就绪拒绝服务。

| 对象 | 本项新增／约束 |
| --- | --- |
| identity_users | ai_enabled 默认 0；未改变旧员工、部门或业务授权 |
| projects／conversations | owner_id 可空以保留历史，revision 正整数；关联两端所有者相同；按所有者和原顺序读取 |
| conversation_messages | owner_id、role（user/assistant/tool）、task_id、提交请求和接受回执；本项仅产生真实 user 消息，助手／工具由 H04 后续接入 |
| tasks | owner_id、revision；扩展 H02 任务状态，来源会话／项目不随补充变更；首条 message_id 保留，后续消息关联同一任务 |
| task_runs | 服务端运行记录：task_id、owner_id、输入 message_id、状态、时间、停止原因、runtime_version；H03 不发起模型、不伪造运行成功 |

所有者为非空时由外键和同所有者关联约束保证图一致；旧 ID、顺序、正文和任务数量保留。任务消息反向关系仅新增明确映射；新增运行表初始为空，不能给历史任务补虚假运行。

任务状态枚举为 `created/running/waiting/completed/stopped/failed/blocked`；运行状态为 `running/waiting/completed/stopped/failed/blocked`。等待原因与停止原因独立记录，`状态确认中`仅为页面状态，不持久化。实际状态转换由 H04 实现。

本项不预建尚未使用的文件目录或通用资产注册器。H06 文件／成果版本和 H07 规则／技能版本应遵守 owner、不可变版本、项目／任务来源与当前授权合同；实际表、文件处理及调用消费者在对应阶段实现。普通附件不能被自动发现为 AGENTS/SKILL 配置。

## 接口与请求兼容

| 入口 | 合同 |
| --- | --- |
| 管理员账号创建／更新、/api/me | ai_enabled 由管理员保存；当前身份返回实际授权，不自动授予业务权限 |
| /api/projects、/api/conversations | 读取返回 owner_id/revision；新增记录自动归本人，拒绝客户端 owner 等未知字段 |
| PATCH 项目／会话 | 明确提供正整数 revision，过期冲突；无 revision 的旧请求返回前置条件错误，旧前端应刷新，不用服务端当前版本补成盲写 |
| 首次 /api/conversation-submissions | 原有 title/project/mode/content/submission_key 保留；事务内接受会话、消息及首条工作任务 |
| 已有会话 /submissions | 可指定 task_id；无 task 时首次创建，一个可继续任务时兼容旧请求，多任务时要求明确选择，不能取最近任务 |
| /api/tasks、/api/tasks/{id} | 本人／管理员无主只读；状态以持久记录为准，latest_run 只指实际运行 |
| /api/tasks/{id}/runs | 授权读取真实运行列表；没有运行返回空，不开放浏览器写运行状态 |
| 技能归属 | 既有技能路径改归 chat，项目技能使用项目内路径；H07 才提供实际技能 API，不为路径映射启用 automation |

重复提交按 owner_id + submission_key 唯一，持久比较首次请求的对象、意图、内容及显式目标。原请求重试返回原接受回执，即使对象改名也不改变原结果；同键异请求冲突。新请求创建下一条消息而不是新建同目标任务，提交接受与 H04 执行启动分开。同一任务有活动运行时，不接受第二条工作运行请求。

运行创建只由服务端控制器调用数据入口，输入消息必须属于同一拥有者和任务。H04 实现实际开始／等待／停止／完成等状态转换及预算；H03 提供真实数据与授权读取，不能用接口测试夹具作为模型运行验收。

已有会话指定任务时还必须满足 `task.conversation_id == conversation_id`；同一员工的其他会话任务也拒绝关联，不搬移来源。验证包括同 owner 跨会话负例。

Word／Excel／PDF 的文件处理和限额归 H06；上传版本、技能版本和规则版本在各自接口实际建立后纳入提交身份比较。H03 不接受未实现的附件、原生 RPC、目录或运行策略字段。

## 消费者与验证

HTTP 数据仍由 api/database.py 内集中管理；api/main.py 处理身份、模块状态、请求模型和错误映射。现有 App、src/api.ts、types.ts 消费 revision 和新元数据；聊天所属 useConversationProject 处理关联忙碌、退出保护与失败对账，账号设置／个人资料使用同一个 ai_enabled；复杂会话 UI 仍在 H05。

聊天和任务以既有静态接入检查的真实模块合同登记，不能伪装为工作台。业务变更声明覆盖权限、数据、公共类型和实际浏览器消费者；必要时扩展已有检查对非工作台模块的覆盖，不另建运行时注册器。

| 验证 | 必须证明 |
| --- | --- |
| 两员工、管理员、失效会话、撤权 | 列表和 ID 不越权，关联不可串 owner，无主只读，当前登录状态校验有效 |
| 并发、幂等、版本 | 一次首次接受一个任务；补充继续任务；原请求稳定回放，同键异请求拒绝；版本冲突不覆盖 |
| 旧历史、迁移和恢复 | 未认领记录与关系保留；旧多任务不合并；新运行不补造；当前快照恢复内容／引用一致 |
| 真实消费者 | 既有 App/输入/任务看板实际调用新接口，账号授权保存有效，失败／冲突不假成功；高级 UI 后续实现 |
| 门禁 | 定向实库后完整 API、Node、模拟／实库浏览器、类型、构建、安全与固定性能预算；不缩减样本或以旧提交替代 |

独立测试集群、数据库、附件、合成账号和随机测试密钥，不使用正式服务或业务数据。冻结 SQLite 仍按原版本与原字段校验，明确映射新列的默认值／已知新 metadata；未知表、列或版本继续拒绝，不能把新 schema 当旧快照来源。

当前原生快照只在匹配 schema／迁移摘要的代码恢复；升级前快照使用对应旧版恢复后显式迁移，不隐式升级或用旧快照覆盖后续合法写入。候选回退优先关闭 AI 入口并保留新记录；H11 内核回退不回退产品数据，正式发布与恢复由 H12/H13 实测。

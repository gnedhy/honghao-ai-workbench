### 采购资讯运行依赖与验收

采购资讯由 `api/procurement_news.py` 调用 `scripts/procurement_news_browser.mjs`，每小时采集商务部、生意社和隆众资讯。运行账号的 PATH 必须能找到 Node.js；实际程序目录必须能解析 `playwright`，且该账号能访问对应版本的 Chromium。Playwright 已列入 `package.json` 的生产依赖，浏览器二进制需单独安装。

新设备拉取代码或更新锁文件后，在项目根目录执行上方依赖安装步骤。若将程序部署到独立版本目录，应一并携带同一提交的 `package.json`、`package-lock.json` 和抓取脚本，在**该候选版本目录**、使用实际运行服务的账号执行：

```powershell
npm.cmd ci --omit=dev
npm.cmd exec -- playwright install chromium
node --input-type=module -e "import {chromium} from 'playwright'; const browser=await chromium.launch({headless:true}); console.log('Chromium OK'); await browser.close();"
```

前端构建在完整开发依赖环境完成，再携带 `dist` 部署；`--omit=dev` 仅用于运行目录。不要仅复制 Python 环境与 `dist`，也不要依赖开发目录的 `node_modules` 或其他账号的浏览器缓存。上述命令按锁文件安装，不使用临时下载的最新版代替项目版本。

部署验收除 `/api/readiness` 外，还须登录采购工作台，在“采购资讯 → 查看全部 → 来源更新状态”确认三个来源成功更新，并能查看资讯。readiness 当前不检查资讯抓取，服务就绪不能代替这项验收。新数据目录启动后即尝试抓取；已有缓存时按上次检查时间等待剩余的一小时间隔，页面每分钟读取一次缓存。

故障时检查实际 `HONGHAO_DATA_DIR/procurement-news/cache.json` 中的 `checked_at`、各来源 `last_success`、`error` 和 `items`。`CollectionFailed` 可由模块加载等采集进程失败引起，先在实际程序目录运行上述浏览器检查；`BrowserUnavailable` 应检查浏览器安装与运行账号。若浏览器检查通过但单个来源失败，再核对该来源的网络和页面解析。缓存独立于采购价格数据，排查时不删除业务数据库或附件。

### 热更新开发与 API 代理

仓库 `npm run dev` 的 API 与 Vite 代理固定使用 8000；与正式服务同机时改用下面的隔离命令。先创建仅在忽略目录使用的 Vite 配置，复用根配置并覆盖代理，避免开发页请求正式 API：

```powershell
New-Item -ItemType Directory -Force .scratch | Out-Null

import { defineConfig } from "vite";
import base from "../vite.config.ts";
export default defineConfig({
  ...base,
  server: {
    ...base.server,
    host: "127.0.0.1",
    port: 4174,
    strictPort: true,
    proxy: { "/api": "http://127.0.0.1:8070" },
  },
});
```

单入口不需要 Vite 代理。使用同一套独立开发配置，先停止占用该开发库的终端 A 实例，再构建并指定隔离产物启动：

代码提交或模块正式启用前运行完整门禁；纯文档修改只检查一致性与引用：

```powershell
npm.cmd run verify
```

`verify` 已包含 `security:check`，同一代码状态不重复运行其中已通过的检查。静态安全检查为只读操作，不能代替独立数据安全审查；发现硬编码凭据、误纳入仓库的数据文件、动态执行、危险 HTML 或未批准的免登录 API 时会直接失败。模块正式启用还必须完成业务确认、数据安全审查、代码审查和回退演练，详见 `docs/security/模块启用审查清单.md`。

PostgreSQL 重启或运行锁连接失效后，旧应用实例拒绝继续数据库操作；须核验数据库后重启应用，重新取得运行锁。关闭应用时会等待正在执行的后台核算结束，再释放运行锁。

默认只监听本机。只有明确配置 HTTPS 和 Windows 防火墙后，才可使用 `--host 0.0.0.0` 暴露到局域网。

### 首次创建本地管理员

数据库须预先配置，不能把 PostgreSQL 集群管理员连接交给业务服务。以全新的 development 库为例，由集群管理员在 `psql` 执行以下准备；用 `\password` 交互设置两个不同密码，不把密码写入 SQL 文件：

```sql
CREATE ROLE honghao_development_migration LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION NOBYPASSRLS;
CREATE ROLE honghao_development_app LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION NOBYPASSRLS;
\password honghao_development_migration
\password honghao_development_app
CREATE DATABASE honghao_development OWNER honghao_development_migration
  TEMPLATE template0 ENCODING 'UTF8' LC_COLLATE 'C' LC_CTYPE 'C';
REVOKE ALL ON DATABASE honghao_development FROM PUBLIC;
GRANT CONNECT ON DATABASE honghao_development TO honghao_development_app;
```

该数据库使用 migration 账号完成 `api.cli migrate` 后，在同库以 migration 账号配置最小业务权限：

```sql
REVOKE CREATE ON SCHEMA public FROM PUBLIC;
GRANT USAGE ON SCHEMA public, honghao_meta TO honghao_development_app;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO honghao_development_app;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO honghao_development_app;
GRANT SELECT ON ALL TABLES IN SCHEMA honghao_meta TO honghao_development_app;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO honghao_development_app;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT USAGE, SELECT ON SEQUENCES TO honghao_development_app;
```

其他环境使用各自的数据库、账号及密码。共享集群还应逐库限制 CONNECT，包括维护库；不能仅依赖不同库名。已配置的数据库不重复建角色或改密码。本机已完成的四库配置见 [第二步记录](releases/PostgreSQL迁移.md#已建立的环境与权限)。

系统不提供默认管理员账号或自助注册。首次启动前交互创建系统管理员；2026-09-10 按用户明确要求，管理界面新增账号默认初始密码为 `123456`，可另设至少12字符的密码；个人修改密码的安全性仅作提醒，不限制最低长度（不能为空、最长1000字符），建议首次登录后修改初始密码。如设置了 `HONGHAO_DATA_DIR`，应先设置环境变量再执行：

```powershell
uv run python -m api.cli create-admin
```

密码使用随机盐和 `hashlib.scrypt` 保存；浏览器只接收 HttpOnly、SameSite=Strict 的本地登录会话 Cookie。账号停用、系统管理权限或范围等级变化后，既有登录会话会立即失效。

权限采用“每个授权范围独立设置”：普通账号可在采购、研发、销售、总经办工作台和知识库分别获得查看、编辑或管理权限。查看只能读取授权数据；编辑可以新建、修改、导入和提交；管理可以审核、退回、确认、发布及管理范围内业务。系统管理独立设置并自动拥有全部范围。部门支持多级组织及一主多兼属，不授予业务操作权限；研发产品读取和维护进一步受部门归属约束，候选适配见 [研发部门数据隔离](business/研发部门数据隔离-2026-10-13.md)，正式启用仍需对应发布。内置敏感字段按所属授权范围校验读取≥2、编辑≥3；未知字段拒绝访问。旧自定义字段策略不再参与现行业务授权，详见 CONTEXT 的权限策略。

“我的账号”只读展示身份与已授权范围，保留修改密码；姓名、部门与权限统一在用户管理维护。左下角帮助入口提供使用说明。意见反馈支持问题、建议和截图，普通用户仅查看自己的记录，管理员负责处理。组织、反馈和界面的现役交接见 [当前交接](<当前交接.md>)。

采购采用共同录价、独立启用授权：编辑人员可录价，管理员及配置的授权管理人员可以授予和撤销启用权；获授权者不能转授权。价格写入受采购范围编辑权限控制，启用另校验独立业务授权。研发独立启用授权及手动成本见 `docs/business/研发受控成本调整-2026-09-14.md`。未启用功能模块从设置隐藏并禁止切换；总经办工作台对所有管理员锁定。采购决策详见 `docs/adr/0007-采购共同录价与正式价格分流.md`。

### 库存数据更新

价格台账默认列为：原料编号、库存量、单位、最新价格、库存价格、价格变化、价格日期、修改人、状态。库存数量保留报表精度，表格仅显示整数部分，鼠标悬停查看完整数值；点击库存量表头可按原始数值升降序排列，实际零库存或缺失显示 `—`，排序仍将零库存视为数值零。库存价格为空或为零显示 `—`。台账的价格变化直接比较本项正式价格与上一次正式价格；仅补充新原料时保留已有原料的价格与比较基准。价格相同显示 0.0%，首次定价或无法比较显示居中的灰底“暂无对比”。排序、筛选和原料详情使用同一口径。价格历史将纯补料单独标明，并仅列本次新增价格；已有原料详情不重复计入补料沿用记录。进入编辑保留库存量等原列顺序，在最新价格后插入待发布价。详见 [台账价格比较与补料历史](<business/价格台账最近调价-2026-09-11.md>)。

数据分流的部门明细直接复用价格台账组件，列、库存与涨跌显示、筛选、排序、个人显示设置和分页保持一致，仅限制部门原料范围。管理员可在表格工具栏点击“调整范围”，从全部原料中跨页勾选，查看新增/移除数并保存；重置、取消和失败重试保留现有行为。范围调整只修改部门关联，不改价格或历史。

管理员使用 `uv run python -m api.cli procurement-inventory <xlsx路径>` 只读预检“原料行情总表”。默认须完整匹配当前在用原料且单位均为 kg；显式加 `--partial` 才只更新表中原料，未列入项目保持原值，空白库存价清空，零库存量保留为零。加 `--apply --actor-id <管理员ID> --sha256 <预检文件哈希> --catalog-sha256 <预检目录哈希>` 执行更新；文件或匹配变化须重新预检。服务及命令使用同一个已明确指定的 `HONGHAO_DATA_DIR`；采购数据结构需先升级至版本 6。

库存通过独立记录关联原料 ID，复用采购来源文件归档，并记录原始库存价、工作表、行号、执行人和时间。相同数据重复导入不重复写入。库存更新不创建调价轮次或价格版本，后续采购录价和启用也不覆盖库存。本次入口为管理员命令，页面“导入报表”仍用于采购价格更新。

### 运维、备份与恢复

统一使用 `uv run python -m api.cli` 管理已明确指定的数据库和 `HONGHAO_DATA_DIR`。结构迁移和实际快照恢复使用 migration 账号，服务、检查、建业务账号及备份使用 app 账号；恢复完成后再切回 app 账号运行服务，不扩大 app 的迁移元数据权限。服务启动不会自动修改数据库结构：

```powershell
uv run python -m api.cli migrate
# 切回同库 app 账号。
uv run python -m api.cli doctor
uv run python -m api.cli backup
```

`backup` 默认在当前数据目录的 `backups/` 创建唯一快照，包含 PostgreSQL 原生数据转储、运行配置、知识原件与 Markdown、采购来源文件，以及文件和逐表 SHA-256 清单。备份期间业务写入暂时等待，读取可以继续。转储使用导出的同一数据库快照；不包含数据库连接密码，但包含业务账号密码的加盐哈希等私密数据，整个备份必须留在受保护存储中。程序、迁移 SQL 与构建产物另行固化。也可指定位置：

```powershell
uv run python -m api.cli backup --destination "D:\HonghaoAI\snapshots"
```

恢复命令默认只做完整性校验，不写入数据：

```powershell
uv run python -m api.cli restore "D:\HonghaoAI\snapshots\snapshot-..." --verify-only
```

恢复只接受与当前迁移版本、运行环境和数据库身份匹配的快照。先用 migration 账号准备一套全新空业务库和空文件目录，再明确指定目标连接与目录；实际恢复继续使用该 migration 账号，因为恢复过程需要写入迁移元数据。不覆盖已有业务库。仍在运行的源服务可以保留，目标库不得有服务连接。确认恢复后，原生工具在单个事务中恢复业务表、序列及采购附件路径；随后核对逐表和附件校验值。失败现场以标记阻止启动，不能自行删标记后继续使用：

```powershell
uv run python -m api.cli restore "D:\HonghaoAI\snapshots\snapshot-..." --apply --confirm RESTORE
```

Windows 更新与回退按以下顺序执行；本次从 SQLite 迁移到 PostgreSQL 另遵守 [六步迁移计划](releases/PostgreSQL迁移.md)，不能直接对正式数据运行下面的结构迁移：

1. 在隔离数据库及附件副本完成代码、数据和业务验证，构建输出到独立目录。
2. 获得正式替换确认后停止正式写入，保留代码、前端、配置和完整数据快照。
3. 使用 migration 账号运行 `migrate`，再切回 app 账号运行 `doctor`。
4. 替换已验证的前端并启动服务，核验登录、台账、编辑及权限。
5. 回退代码必须使用匹配的结构版本；需要恢复数据时，恢复到新空库和新目录后核验，再切换连接。禁止覆盖唯一的正式数据。

开机运行由 IT 按 [当前发布记录](releases/销售报价正式部署-2026-09-24.md)配置固定版本目录的启动入口；不依赖开发工作区。每个实例使用独立数据库与 `HONGHAO_DATA_DIR`。

### 顶层功能模块状态

测试环境默认只启用工作台，知识库、AI 会话、自动化和任务看板保持关闭；全新的正式环境默认关闭全部模块。系统管理员在“系统设置 → 常规”中通过开关调整启用状态，界面仍显示原型、启用或关闭的实际模式；保存后显示为待生效状态，重启当前服务后应用。配置保存在当前 `HONGHAO_DATA_DIR`，不会影响另一套实例。

测试环境仍可在首次启动时使用环境变量指定初始状态：

```powershell
$env:HONGHAO_MODULE_WORKBENCH_MODE = "active"
$env:HONGHAO_MODULE_KNOWLEDGE_MODE = "off"
$env:HONGHAO_MODULE_CHAT_MODE = "off"
$env:HONGHAO_MODULE_AUTOMATION_MODE = "off"
$env:HONGHAO_MODULE_TASKS_MODE = "off"
# 设置完成后按上方隔离启动方法运行。
```

- `active`：开放真实功能。
- `prototype`：开放并明确标注为功能原型。
- `off`：隐藏入口，相关业务接口同时返回不可用。

配置缺失时使用上述默认值；配置值非法时服务拒绝启动，不会静默开放模块。

正式环境禁止通过 `HONGHAO_MODULE_*_MODE` 绕过后台门禁。首次启用或启用边界修订后，管理员必须确认业务负责人、数据安全、代码审查和回退演练四项均已通过；已有有效记录的恢复启用仅需再次确认，不要求手填 Issue/PR 地址。审查确认随待生效配置保存，重启时再次校验，详见 [启用确认简化](<business/启用确认简化-2026-09-10.md>)。发布仍由管理员或 IT 使用审核后的版本标签手动完成；系统不提供一键发布。

### 职能工作台模块状态

四个职能工作台在开发环境默认保持原型，可分别切换为 `prototype`、`active` 或 `off`。采购、研发与销售已接入真实模块，正式环境通过持久配置启用；总经办的真实模式仍使用安全阻断页。以下是开发模式示例：

```powershell
$env:HONGHAO_WORKBENCH_PROCUREMENT_MODE = "prototype"
$env:HONGHAO_WORKBENCH_RESEARCH_MODE = "prototype"
$env:HONGHAO_WORKBENCH_SALES_MODE = "prototype"
$env:HONGHAO_WORKBENCH_MANAGEMENT_MODE = "prototype"
# 设置完成后按上方隔离启动方法运行。
```

- `prototype`：显示明确标注的示例界面。
- `active`：启用真实模块；总经办等尚未接入的工作台会安全阻断，不展示示例数据。
- `off`：隐藏该职能入口；后续真实业务接口也必须使用同一开关阻断。

配置只在启动时读取，修改后需要重启。影子验证应使用单独的 `HONGHAO_DATA_DIR` 和测试数据副本；正式实例发生异常时，先把对应模块切回 `prototype` 或 `off`，不要删除模块数据。标签 `workbench-ui-baseline-2026-08-25` 仅为早期 UI 历史，不是当前版本的默认恢复基线。

采购支持 CSV、TXT、单表 XLSX 和复制粘贴导入预览，台账展示最新价格，通过替代记录保留修正链，授权启用后形成不可变价格版本。采购接口限定在 `/api/workbenches/procurement/*`，数据使用独立的 `procurement_*` 表和 `workbench_procurement_schema_version` v7；核心 schema 保持 v5。原料价格与询价记录按采购范围权限校验。

原料台账与本轮更新共用一张工作表；有活动更新时显示待发布价和行内补价；行内波动确认仅用于遗留未确认事项或重新核对，启用后恢复日常正式价格列。日常列偏好与本轮临时列设置分离。现有批次响应新增 `input_items`，包含该批次录入或复制的候选项（含未变价、零价和缺价）；原 `items` 仍只返回变价明细。前端按归属区分未调整与待补价，不根据空价格或日期猜测。

“编辑价格”支持台账跨页输入后统一保存；统一价格日期和修正原因，清空输入只撤回未保存修改，不删除已有报价。`POST /api/workbenches/procurement/prices/bulk-adjustments` 复用单项录价存储逻辑，在同一事务内完成整批写入，并校验编辑开始时的批次标识和更新时间；冲突或任一行失败均不写入。启用前，最新价格保持不变；批量确认窗口将原因和参考价一起提交，保存与波动确认在同一事务完成。价格基准或参考价变化时拒绝过期确认，输入保留供重新核对；未携带确认信息的单笔或旧接口仍保留待确认门槛。“取消更新”在本轮操作区以二次点击确认；只读操作记录使用抽屉，不占用表格高度。未保存修改在离开前提示，日常列偏好保持独立。

每轮候选价格使用现有工作批次明细保存，发布时由当前正式基线合并该批次变更；未录入项目保留正式价，缺价或未确认波动阻止启用。排期与已取消草稿不会混入下一轮；重新录入会重新计算风险，当前入口在保存时确认本次新价格；基线变化仍会使对应风险确认失效。正式价日期使用 `published_price_date`，询价日期继续使用 `price_date`。价格批次可打开只读快照，定时版本同时显示批准人和系统启用方式。

单机服务启动时补处理到期排期，运行期间每30秒检查，状态纳入 `/api/readiness`。暂停服务期间不会自动启用；新正式基线会将旧排期置为需要重新确认。采购回归测试使用独立临时数据目录，不能在当前演示库执行导入、取消或启用测试。

模块结构迁移前保存完整 PostgreSQL 快照。旧的 `scripts/backup_database.py` 只用于离线保存尚未迁移的 SQLite 数据，不能作为 PostgreSQL 运行或备份入口：

```powershell
uv run python -m api.cli backup --destination "D:\HonghaoAI\snapshots"
```

统一验证命令（须注入专用隔离测试库的 app、migration 连接；恢复测试还需可创建临时测试库的集群账号，见 [迁移记录](releases/PostgreSQL迁移.md)）：

```powershell
npm.cmd run verify
```

接口测试固定使用本机 `honghao_test`：`HONGHAO_TEST_DATABASE_URL` 为 `honghao_test_app`，`HONGHAO_TEST_MIGRATION_URL` 为 `honghao_test_migration`，恢复测试的 `HONGHAO_TEST_CLUSTER_URL` 为本机维护库的测试建库连接。每个用例重建该测试库的 public 结构；不要向此库存放业务或验收数据。测试进程持有独占锁，不能同时启动两套接口测试。Windows 同时设置 `PYTHONUTF8=1`。底层事务和迁移专项另运行 `uv run python -m pytest tests_postgres`。

2026-10-15 导入候选的服务连接由 `service_marker` 随服务启动和退出管理：使用 Psycopg 官方连接池，最多4条业务连接、等候5秒；独立服务锁连接不进池。事务仍逐次读取权限，查询采用同一只读快照，写入保留事务锁；归还连接时 `DISCARD ALL` 清除会话设置、临时对象和会话锁，关闭自动预备语句以免客户端缓存与清理后的服务端不一致。服务锁失效时拒绝业务请求。迁移、恢复和离线命令默认继续使用直接连接；没有新增业务数据缓存或权限缓存。依赖与版本固定于 `pyproject.toml`、`uv.lock`。

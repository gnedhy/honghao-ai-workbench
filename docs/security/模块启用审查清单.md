# 模块启用审查清单

本清单适用于每个功能模块和职能工作台从 `prototype` 切换为 `active`。四项结论必须全部完成并保存，缺一项时正式环境拒绝启用。

## 1. 业务负责人确认

- 固定业务样本的输入、计算结果和历史版本已经对照确认。
- 写入、审核、退回、发布和禁止自审的边界符合实际流程。
- 空状态、无权限、接口失败及模块关闭状态不会误导用户。

## 2. 数据安全审查

- 身份与授权：匿名、越范围、低等级和失效会话请求均被服务端拒绝。
- 敏感字段：读取与编辑分别按授权范围和最低权限控制，响应不会泄漏被过滤字段。
- 文件边界：上传只接受允许的类型和大小；文件名不能决定存储路径；原件下载必须重新校验权限。
- 目录边界：业务代码只能访问当前数据目录和受控工作目录，不能读取任意本地路径。
- 日志与审计：只记录主体、动作、对象和时间，不记录密码、令牌、敏感字段值、完整正文或模型隐式推理。
- 密钥与网络：仓库和构建产物不含密钥；新增外部请求必须列明目标、数据范围、超时及关闭方式。
- 内容执行：禁止动态执行、未经净化的 HTML 和来源不明的脚本。

## 3. 代码审查

- `npm run verify` 全绿，测试没有减少，且没有 skipped、todo 或忽略失败的写法。
- `npm run security:check` 全绿；密钥、数据文件、动态执行和未批准免登录 API 均未出现。
- 依赖来源、锁定版本、许可证和安全审计已更新至《依赖审查台账》；PDF、Harness、MCP 单独复核。
- 变更仅位于模块作用域，不修改中台公共布局、全局样式或其他模块状态。
- 对越权、越界、重复写入和失效审查具有反向测试。

## 4. 回退演练

- 已在独立 `HONGHAO_DATA_DIR` 使用测试数据完成一次 `active → prototype/off → active` 演练。
- 降级后中台、知识库和其他模块仍可使用，模块数据继续保留。
- 重新启用后能够读取原数据；必要时已验证备份与恢复命令。

## 证据保存

- 对应 GitHub Issue 保存业务样本、数据安全结论和回退演练结果。
- 对应 Pull Request 保存代码审查结论、测试结果和依赖变化。
- 正式启用界面保存四项完成状态、实际确认人、时间及启用边界修订号，不再要求手填 Issue/PR；旧记录中的链接兼容保留。已有有效记录的恢复启用只需再次确认，边界修订变化后重新完成四项。Issue/PR 仍用于存放开发证据，不由系统伪造链接。启用与降级历史追加保存，不因切回原型或关闭而删除；运行配置不保存业务正文或敏感值。实现说明见 [启用确认简化](../启用确认简化-2026-09-10.md)。

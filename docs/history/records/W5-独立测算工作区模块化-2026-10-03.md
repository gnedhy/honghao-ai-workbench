## 修复及必要权限调整

| 问题 | 处理与对应检查 |
| --- | --- |
| 保存等待期间新输入被旧回包覆盖 | 只在输入仍等于提交指纹时应用归一化回包，否则保留输入并显示尚未保存。`red-input.log` 在原组件真实复现 9→4；新输入 9、原实存 4、再次新增实存 9 分别验证 |
| 慢历史 GET 覆盖保存／删除结果 | 成功写入增加读取版本，过期回包重读。GET 先看见已提交对象时，保存回包按 ID 去重；工作区和模板同样处理 |
| 未应用分档或模板名无确认丢失 | 面板草稿参加退出 dirty；取消保留值，自定义模板名不随外部 blur 消失。打开／重置递增 epoch，清理局部展开、拖拽和草稿 |
| 替换公式后隐藏草稿持续阻止保存 | 恢复公式、切类型、载入模板或移除自动公摊使目标步骤失效时清理分档提议；真实操作恢复后完成保存 |
| 手工成本改回保存值仍显示未保存 | 成本编辑保留归一化来源字段；`red-restored-cost.log` 复现保存 9 后改 8 再改 9 仍 dirty。第一真实场景补恢复 clean、鼠标退出无确认及仅两次新增的检查 |
| 等级 2 无法调用只读测算 POST | `green-five4.log` 真实 HTTP 返回 403。全局原先将全部 POST 归为写操作；`api/main.py` 仅对精确 `POST /api/workbenches/sales/calculator/evaluate` 按读取等级检查，销售 router／Store 仍要求销售等级 ≥2 |

权限修正按现行约定单独审查：认证、模块状态和可用性检查保留，其他 POST／PUT／DELETE 仍按写入门禁，保存／修改／删除仍要求销售等级 ≥3，所有者与 revision 校验不变。没有改变 HTTP 请求／响应形状、历史新增语义或公式。后续发布须包含该后端修复，不能只换前端就称等级 2 修复上线。

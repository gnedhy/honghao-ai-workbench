## 接口扩展子项与兼容方案

现有创建接口不能区分“创建失败”和“创建已提交但响应丢失”；仅保存已收到的阶段结果不足以处理后一种情况。因此在实现前单独审查以下扩展。

- `POST /batches`、`PUT /batches/{id}/draft`、`POST /batches/{id}/calculate` 增加可选 UUIDv4 `request_id`；未提供字段时维持旧行为。采用、调整、作废等接口不扩展。
- 创建复用请求 ID 为现有批次主键。相同请求只在操作者、原始创建请求摘要、版本 1 全部一致时返回第一次结果；同 ID 异内容、其他归属和后续版本拒绝。复制批次不重新读取变化后的来源。
- 草稿和测算在批次 payload 保存最近一次成功请求的 ID、摘要与结果版本；摘要绑定操作、操作者和完整原请求。先执行现行授权及归属检查，再检查重放凭据，再检查旧版本。同请求同结果版本重放不追加事件或测算；后续操作已更新版本则保留 409，不自动覆盖。
- 摘要在业务逻辑规范化或修改请求之前计算。前端保存失败阶段的原始请求，重试先确认该阶段，再使用当前输入继续；每个已成功阶段都保留批次 ID 和版本。确定的 422 校验失败允许修正输入；401、403、409停止后续写入。
- 保存只有全部必要阶段完成后才建立干净指纹、开放采用；中断不能用旧指纹让新草稿进入采用。忙碌期间锁定编辑区并阻止重复保存。

独立只读审查 `/root/w1_review` 已检查 #60、销售完整生命周期及事务实现，同意该最小方案，并提出上述摘要时机、授权顺序、完整保存标记和确定失败处理四项必要条件。未由审查者运行数据库或浏览器测试。

不增加表、列、索引或迁移；复用 `digest`、`transaction`、`createClientId`。旧代码可忽略新增 payload 元数据，旧请求不需要幂等字段。恢复旧代码后不得继续宣称新请求可幂等重试。最近一次凭据只保证版本未再变化时的重放；编辑器恢复范围为当前挂载会话，刷新或关闭后不自动重放未知请求。

### 实现与状态归属

- 退出修复只将报价编辑器接入现有 `sales-before-leave`；未重写 `App`、共享调度或确认组件。编辑器卸载仍由原 Hook 清理事件、beforeunload 和待决 Promise。
- `savedBatch` 保留每一步收到的成功 ID／revision；`savedDraft` 保存已确认草稿及输入指纹；`pendingWrite` 保留尚未明确成功的原请求。422清掉已确定拒绝的请求，401／403／409不自动绕过。完整保存前失效干净指纹，失败后仍保留当前输入。
- 保存与采用共用同步忙碌锁，阻止同一事件周期重复操作。编辑区使用原生 inert；操作栏在 inert 外保持状态可读，忙碌时取消、保存、采用及关闭禁用。
- `fetchJson` 保留原 `Error`、文案和消息解析，仅附加 HTTP `status`，供报价区区分422与未知提交。采购、研发、测算等已有消费者仍按原错误文案处理。

### 旧路径与候选

旧路径复现使用 `W2_BASELINE=1` 加载 W1 提交的原报价组件，并使用保留旧无 `request_id` 行为的测试 API。五种中断——草稿写前失败、测算写前失败、创建／草稿／测算事务提交后响应丢失——每次重试都实际出现两个测试批次；同一事件周期两次 DOM click 发出两次创建，统一退出也误返回 true。实际抽屉直接关闭保护原本仍能工作，不将该发现写成生产丢数事故。旧路径原始7项检查返回非零。

候选复用相同联通入口，真实响应丢失在 `route.fetch` 已收到200后注入 `route.abort`，不由模拟接口代替数据库。对同一输入重试，结果为一个批次、revision 3、一次测算、三个事件；已成功阶段不重复写入。中断后改输入先确认旧请求，再形成新版本，两个测算对应两个不同输入快照；不会把旧响应覆盖到新输入。

# V0.3 Taste 视觉评审

## 结论

V0.2 的信息架构和页面布局保持不变。V0.3 只优化视觉层级、控件质量、排版、颜色、间距和状态反馈，不新增功能，不改变“会话优先、任务沉淀”的产品方向。

推荐以 [Taste 融合候选 V0.3](<../README.md>) 作为前端视觉基准，进入代码前仍需人工确认。

## Design Read

这是一个面向企业内部知识工作者的高密度 AI 工作台重设计：保留现有信息架构与文案，以冷静、可信、精密的产品语言呈现，采用 Fluent UI v9 的可访问控件基础，并叠加自有钴蓝与石墨灰视觉令牌。

## 视觉参数

- 设计变化度：4/10。保留既有布局，以细节和秩序提升为主。
- 动效强度：3/10。只服务于状态反馈、焦点移动和任务进度。
- 信息密度：7/10。满足日常企业工作，不做营销页式大留白。

## 两个 Taste Skill 的使用边界

### GPT Taste

其强项是品牌感、排版、对比和动效节奏，但默认方法更接近营销网站。本项目只采用以下部分：

- 更明确的字体层级与数字排版；
- 统一的间距、圆角和阴影规则；
- 降低模板化卡片堆叠；
- 为输入区、焦点和时间线提供轻量状态动效。

不采用 AIDA 页面结构、超大标题、滚动叙事、装饰性 GSAP 动画和强营销视觉。

### Design Taste Frontend

该 Skill 明确指出密集型产品界面不应直接套用落地页方法，并建议企业 SaaS 采用正式设计系统。因此本项目采用：

- Fluent UI v9 作为控件、键盘操作、焦点态和可访问性基础；
- 自定义颜色、字体与密度令牌，避免成为通用后台模板；
- 一个主强调色，不使用 AI 紫色或装饰性渐变；
- 只在形成明确分组时使用容器，主要内容尽量采用开放式分区；
- 使用统一图标家族，不混用手绘图标；
- 使用轻量 Motion 状态过渡，不采用滚动驱动动画；
- 完整设计加载、空状态、错误、禁用、等待确认和降低动态效果状态。

## 三个方向的比较

| 方向 | 优点 | 风险 | 处理结论 |
| --- | --- | --- | --- |
| A 墨蓝编辑系统 | 品牌识别强，主次对比清楚 | 深色侧栏较重，容易抢主工作区 | 保留字体对比与品牌感，不作为默认主题 |
| B 雾蓝精密 | 最接近当前使用习惯，清晰、稳定、可扩展 | 如果缺少自定义令牌，容易显得通用 | 作为融合稿的主基础 |
| C 石墨纸张 | 严肃、克制，状态标记清楚 | 亲和力较弱，侧栏重量偏高 | 吸收状态标记和纸张感，不作为默认主题 |

## 推荐视觉系统

### 颜色

- 页面背景：暖白，不使用纯灰大底。
- 导航区：浅雾蓝灰，与工作画布保持清楚但低对比的分区。
- 正文：石墨灰，避免大面积纯黑。
- 主强调色：钴蓝，只用于当前选中、主要操作和运行中状态。
- 语义色：绿色表示完成，琥珀色表示等待确认或提醒，红色只表示真实错误或危险操作。

### 字体与密度

- 中文优先保证系统可读性，采用现代无衬线字体栈。
- 拉丁字符、时间、版本号和代码内容使用清晰的等宽或数字友好字体。
- 以 8px 为基础间距节奏，正文与辅助信息通过字重、字号和颜色共同分层。
- 默认适配 1440px 桌面工作区，同时预留较窄窗口下的侧栏收起策略。

### 形状与层级

- 常规控件和容器统一使用 6px 至 8px 圆角。
- 头像保持圆形；分段标签可使用胶囊形，但不把所有按钮都做成胶囊。
- ChangeSet 与底部工作输入区可以有轻微抬升，其余区域优先使用分隔线和留白建立层级。
- 侧栏选中态使用浅色底与窄色条，不使用厚重的大圆角块。
- 设置入口只存在于个人资料菜单，不在侧栏底部单独放齿轮。

## 动效原则

- 输入区获得焦点：轻微上移并增强边框，150ms 至 200ms。
- 页面标签切换：指示条平滑移动，内容使用短距离淡入。
- 任务进度：状态点与连接线更新，不持续循环闪烁。
- ChangeSet 出现：使用透明度与少量位移，不使用弹跳。
- 尊重 `prefers-reduced-motion`，降低动态效果时取消位移和连续过渡。

## 内容与实现边界

- V0.3 图片是视觉参考，不是字段和文案的最终权威来源。
- 页面结构、菜单命名、字段、状态和审批逻辑以 V0.2 信息架构及开工文档为准。
- 图片生成中出现的示例时间、版本、措辞和数据不得直接写入产品逻辑。
- 前端实现前先提取颜色、排版、间距、圆角、阴影、图标和状态令牌，再搭建页面。
- 当前尚未开始前端代码开发。

## 验收标准

- 四个一级菜单和各页面顶部分段标签保持既定结构；
- 设置只从个人资料菜单进入；
- 聊天与工作模式可一眼区分；
- 任务步骤、等待确认、ChangeSet 和主操作层级清楚；
- 不依赖颜色也能理解关键状态；
- 键盘焦点、禁用态、错误态、空状态和降低动态效果状态可实现；
- 视觉确认后再进入 React 前端骨架。

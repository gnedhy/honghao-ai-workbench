# 宏昊 AI 平台开发总计划

日期：2026-08-25
状态：历史路线图；2026-09-09 起的当前范围以 [ADR-0008](<../../adr/0008-工作台优先与候选验收边界.md>) 为准，后续模块及顺序待重新评估。
任务跟踪：[GitHub Issue #28](https://github.com/gnedhy/honghao-ai-workbench/issues/28)

## 1. 目标与当前策略

宏昊 AI 不一次开放全部功能。当前只开放职能工作台，先接入采购、研发、销售和总经办的确定性业务能力；知识库、AI 会话、自动化和任务看板只有在各自真实数据、权限、安全和回退闭环完成后才启用。

开放顺序：

`工作台 → 知识库 → 任务看板 → AI 会话 → 自动化`

“只开放工作台”不等于只有前端页面。正式接入第一个模块前，必须具备服务端模块开关、本地账号、分层权限、敏感字段策略、PDF 原件与 Markdown 来源链、完整备份恢复、正式启动入口、安全审查和审计。模型、Harness、MCP 和 Workflow 不阻塞确定性成本计算；某个工作台确需 AI 时，该子功能保持关闭，直到运行底座通过验收。

范围变更说明：早期 V0.1 文档把多用户放在暂缓范围，是为了先验证单机原型；本路线图面向真实工作台数据，已将本地账号和权限提升为 Phase 0 前置。早期文档作为历史决策保留，不回写成当前实施依据。

## 2. 总体架构

```text
React 产品外壳
  ├─ 工作台 / 知识库 / AI会话 / 自动化 / 任务看板
  ↓ HTTP + SSE
FastAPI 产品层（业务事实源）
  ├─ 模块注册、账号权限、知识文档、职能业务
  ├─ 会话、任务、运行、审批、Skill、Workflow
  └─ SQLite 元数据 + Markdown/PDF 文件
  ↓ HarnessRuntime 稳定接口
MockHarnessAdapter  |  DeepSeekHarnessAdapter
                           ↓ JSON-RPC stdio
                    锁定版本 Node Sidecar
                           ↓
                  模型 / Tool / 受控 MCP
```

产品层不认识 Cordis、Profile、Agent 或 SessionEvent。DeepSeek Harness 只负责运行内核，不能拥有用户、知识、任务、Workflow、权限或正式写入。官方项目仍处于开发预览并明确提示会发生破坏性变化，因此只能锁定版本并通过 Adapter 隔离。[DeepSeek Harness README](https://github.com/deepseek-ai/deepseek-harness)

## 3. 技术栈

| 层 | 当前选型 | 负责内容 | 暂不引入 |
|---|---|---|---|
| 前端 | React 19、TypeScript、Vite、现有 CSS 体系 | 产品外壳、响应式页面、权限后的交互 | 新 UI 库、微前端、第二套路由框架 |
| 产品后端 | Python 3.12、FastAPI、Pydantic | 身份、权限、知识、业务状态、HTTP 接口 | 拆微服务、GraphQL |
| 元数据 | Python `sqlite3`、增量迁移 | 业务事实、权限、版本、运行与审计 | PostgreSQL、ORM 大改 |
| 文件资产 | Markdown、PDF、SHA-256 清单 | 知识正文、原件、来源与可恢复资产 | 对象存储、云文档平台 |
| 检索 | SQLite FTS5 + 短中文受限 `LIKE` | Markdown、PDF 提取文本和元数据检索 | 向量数据库、Elasticsearch |
| 后台执行 | 单 Python worker、SQLite 租约 | 任务领取、重启恢复、取消、事件落库 | Celery、Redis、分布式队列 |
| 实时进度 | SSE | 服务端向页面推送已持久化运行事件 | WebSocket 双向协议 |
| 模型 | Mock Provider + 1 个 OpenAI 兼容 Provider | 可替换模型调用、用量与错误归一 | 多模型路由、自动降级 |
| Harness | Mock Adapter + 锁定版本 DeepSeek Harness Node Sidecar | 有界 Loop、工具调用、取消、执行证据 | DeepSeek Web UI、直接绑定内部接口 |
| Skill | `SKILL.md` + `manifest.json` + JSON Schema | 版本化能力、输入输出和样本 | Skill 商店、在线协同编辑 |
| Workflow | JSON 定义 + Pydantic 校验 + SQLite 状态 | 固定节点、等待、人工关口、恢复 | 拖拽编排、动态生成流程 |
| Tool/Connector | 静态 ToolRegistry + 本地/HTTP/MCP Adapter | 可执行能力、外部系统连接 | 任意插件安装、无审批写入 |
| 运维 CLI | Python 标准库 `argparse` | 管理员、迁移、备份、恢复、worker、诊断 | Typer/Click 等新框架 |
| 正式启动 | FastAPI 同源托管 Vite 构建产物，默认绑定 `127.0.0.1` | 一个命令启动、健康/就绪检查、明确数据目录 | Electron、容器编排、Windows 服务 |
| 验证 | pytest、TypeScript 构建、内置浏览器；真实模块阶段补 Playwright | 接口、状态、安全、桌面/移动端 | 只看页面截图代替业务验证 |

### CLI、MCP 与 Plugin 的准确职责

- **CLI 必须有**：它是管理员与本地运行入口，用于创建首个管理员、迁移、完整备份、恢复校验、启动 worker、查看健康状态和诊断 Sidecar；普通员工不使用 CLI。
- **MCP 后置**：它是外部工具的传输 Adapter，不是知识库、Skill 或 Workflow。只有接 ERP、CRM、企业微信等真实系统时，才为单个服务器建立白名单、权限、密钥、网络出口和回退 Issue。
- **DeepSeek Harness Plugin 不对员工开放**：只允许 Sidecar 配置中锁定的内部 Plugin。产品界面中的“插件”应表达为“连接器/工具”，不得开放任意 npm、命令或 MCP 安装。
- **不使用官方 Python SDK 作为当前 Windows 主通道**：官方入门文档当前列出的运行平台不含 Windows；现阶段继续使用独立 Node Sidecar，通过 JSON-RPC stdio 接入 FastAPI。[Python SDK 指南](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/python-sdk.md)
- **正式运行仍是单进程产品服务**：由现有 FastAPI 同源提供 API 和前端静态文件，CLI 只包装启动和诊断，不再建设第二套服务器。需要局域网访问时再增加 HTTPS 反向代理和网络边界审查。

## 4. 核心模块与接口 seam

### 4.1 ModuleRegistry

固定管理 `workbench、knowledge、chat、automation、tasks`，状态为 `off、prototype、active`。服务端是唯一事实源；模块关闭时同时隐藏导航并停止业务接口。它只管理状态，不变成动态插件系统。

### 4.2 IdentityAccess

本地账号、会话、角色、模块/操作权限、资料 ACL、敏感字段策略和审计集中在一个授权 seam。工作台模块声明字段目录，管理员从目录选择敏感字段并配置可读/可写角色；无权字段从返回数据中完全移除。权限失败必须在服务端阻断，不能依赖前端隐藏。

### 4.3 KnowledgeRepository

PDF 是不可变来源文件，Markdown 是可审查、可发布的知识版本，两者分别授权并长期关联。第一阶段只解析含文本层的 PDF；扫描件保留原件并标记待 OCR，不调用云 OCR。个人与公共知识、原件预览下载、版本发布和全文检索共用一个来源模型。

### 4.4 BusinessWorkbench

四个职能工作台使用现有静态 WorkbenchId 和公共外壳，各自拥有业务页面、接口、字段目录和独立前缀数据表。采购发布确认原料成本版本，研发引用该版本，销售引用确认产品成本，总经办只读汇总确认数据。历史引用不得被上游更新改写。

### 4.5 HarnessRuntime

外部接口保持 `run(request)` 与 `cancel(run_id)` 两个操作；恢复继续调用 `run` 并携带检查点。Mock 与 DeepSeek 两个 Adapter 共享同一事件与停止原因。产品只持久化标准化 RunEvent，不保存模型隐式推理。

### 4.6 Workflow、Loop、Skill 与 Tool

- Workflow 是外层固定业务流程，决定节点顺序、人工等待和正式写入。
- Harness 承载一次运行，并发放模型、知识和工具能力。
- Loop 是 Harness 在一个智能节点内的“理解—计划—执行—观察—判断”有界迭代，必须受步骤、时间、模型、工具和费用预算限制。
- Skill 是版本化的判断或生成能力，不直接拥有外部权限。
- Tool/Connector 是可执行能力；写操作必须形成预览或待确认修改。
- MCP 仅是 Tool Adapter；Harness Plugin 仅是 Sidecar 内部包装方式。

### 4.7 AI 会话与任务

聊天提交通过受限 Harness 会话运行，但不创建 Task，不进入任务看板；默认只能读取用户附件和获权知识。工作提交创建 Task，由 worker 执行 Workflow/Harness。任务看板只是 Task、TaskRun、RunEvent、Checkpoint 和待确认修改的投影，不实现第二套状态机。

## 6. 数据、安全与回退门槛

- 核心 `schema_version` 保持 v5；身份、知识、运行和各工作台使用独立版本键，迁移只新增表、字段和索引。
- 每个 PR 前停止正式实例，备份 SQLite、Markdown、PDF 和哈希清单，并在副本验证迁移。
- 模块合并后先保持 prototype，在独立 `HONGHAO_DATA_DIR` 影子运行；业务负责人、数据安全审查和代码审查通过后才 active。
- 每个真实模块 PR 必须关联字段目录、权限矩阵、数据迁移、回退步骤和审查记录；缺少任意一项不得合并为 active。
- 文件、模型、MCP 和 HTTP 出站全部使用白名单；Windows 沙箱能力若只能部分执行，必须明确显示，不得宣称完全隔离。DeepSeek Harness 官方也将 Windows ACL 后端标记为部分执行场景。[Sandbox 文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/sandbox.md)
- 正式知识、项目卡、成本版本和报价只能经待确认修改或业务确认接口写入；Harness、Skill、Tool 和 MCP 均不能直接绕过。
- 日志只保存恢复和审计所需的结构化事实，不保存密钥、完整敏感正文、模型隐式推理或未脱敏工具结果。

## 7. 升级技术栈的触发条件

只有出现真实证据才升级：

- SQLite 出现持续写锁、需要多个 worker 或中央服务器多进程部署时，再评估 PostgreSQL。
- 单 worker 无法满足已测任务吞吐或故障隔离时，再引入队列；不是因为任务“看起来可能很多”。
- FTS5 在真实 TDS/制度样本中召回不足且人工验证证明语义检索有收益时，再增加嵌入与向量索引。
- 原件容量、备份时间或多机共享超过本地文件系统能力时，再评估 MinIO/S3。
- 明确第一个外部系统和读写动作后，才启用真实 MCP/HTTP Connector。
- 团队共享部署、离开本机或需要企业身份统一时，再接 HTTPS 反向代理和 SSO。

## 8. 总体验收

- `npm run verify` 不回退，测试不得 skip/todo 或放宽断言。
- 每个模块验证 off/prototype/active、接口故障、桌面端和 390px 移动端。
- 每个高风险能力做一次反向验证：越权字段、目录穿越、未授权原件、未批准MCP、超预算Loop、重复写入和恢复必须真实失败。
- DeepSeek Sidecar 不可用时，业务数据、工作台和知识仍能读取，Mock Adapter 能继续自动化验收。
- 任何阶段失败均可切回 off/prototype 或回退独立 PR；数据默认保留，只有迁移损坏或错误批量写入才恢复备份。

# 输入上下文、固定对话列与双模式侧栏验证记录

## 本轮目标

1. 让项目、知识库和计划模式采用一致的已选状态与移除反馈。
2. 让已有聊天和已有工作的正文与输入框保持同宽，并把输入框固定在工作区底部。
3. 重新划分聊天与工作右侧栏职责，避免与主界面导航或输入区重复。

## 输入上下文规则

- 工作模式顺序固定为：加号、项目、知识库、计划模式。
- 项目始终位于第一项，不因启用知识库或计划模式而移动。
- 项目、知识库和计划模式平时显示各自图标；悬停或键盘聚焦时切换为关闭图标，点击后移除。
- 新建空状态的菜单向下展开；已有对话的输入框固定在底部，因此菜单改为向上展开，避免越出视口。

## 已有对话布局

- 聊天与工作使用相同的 750px 最大阅读宽度。
- 消息、诊断卡、ChangeSet 和输入框左右对齐。
- 输入框固定在中间工作区底部；上方聊天记录或执行过程独立滚动。
- 右侧栏展开后，中间阅读列在剩余空间内重新居中。
- 390px 宽度下自动缩至 366px 可用宽度，无横向溢出。
- 用户消息使用右侧浅灰气泡，助手回复保持无气泡正文，工具动作使用轻量状态行。
- 新建与已有对话共用同一套柔和输入框投影；已有对话底部预留完整的阴影淡出空间。

## 右侧栏职责

### 聊天模式：对话上下文

- 本次上下文：知识访问、当前引用、本次附件。
- 对话边界：会话类型、写入权限、知识沉淀规则。
- 不显示工作目录、暂停任务或任务看板入口。

### 工作模式：执行控制

- 执行环境：知识范围、执行模型、受控工作目录。
- 新工作显示执行边界；已有工作显示当前检查点、进度与暂停或继续操作。
- 不重复左侧任务看板入口。
- 文件写入继续以 ChangeSet 人工确认作为安全边界。

## 验证结果

- 工作输入区顺序为“加号、项目、知识库、计划模式”。
- 已选知识库和计划模式都具备悬停或聚焦切换关闭图标的反馈。
- 桌面端聊天与工作正文、输入框实测均为 750px。
- 390px 下聊天与工作输入框均为 366px，页面滚动宽度为 390px。
- 390px 最终聊天输入框底部位于 822px，保留 22px 投影淡出空间。
- 聊天右侧栏不再出现任务控制；工作新建状态不再出现无意义的暂停任务。
- 工作右侧栏不再重复任务看板入口。
- `npm.cmd run typecheck`：通过。
- `npm.cmd run build`：通过。
- `npm.cmd audit --omit=dev --offline --audit-level=high`：0 个漏洞。
- 高风险前端模式扫描与 `git diff --check`：通过。
